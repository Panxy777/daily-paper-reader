## 摘要
专家并行（EP）通过将大型混合专家（MoE）模型的专家分布到多块 GPU 上，使其推理成为可能，但需要在每个 MoE 层进行大量 GPU 间通信。随着当代 MoE 模型为每个 token 激活更多专家，这种通信在推理时间中所占比例不断上升。在基于 PCIe 的消费级 GPU 系统上，这一开销尤为显著，因为所有 GPU 间传输都要经过 CPU 内存。然而，现有专门面向 MoE 的 EP 通信库假设可直接进行 GPU 到 GPU 访问，在很大程度上忽略了消费级 GPU。因此，大多数 LLM 框架转而依赖 NCCL，而其经 CPU 中转的通信会引入冗余 PCIe 传输，并与专家计算争用 GPU 资源，从而限制二者重叠。我们提出 ThunderEP，这是一种面向此类系统的新型通信设计，它消除了传统 ring 算法的中继跳数，通过 DMA 引擎搬移数据以避免计算资源争用，并通过降低 CPU 内存中完成标志的轮询开销来最小化同步延迟。我们将该设计集成到 vLLM 中，并在三个广泛使用的 MoE 模型上进行评估。在配备 RTX 4090 和 RTX 5090 GPU 的两个 PCIe 系统上的实验表明，ThunderEP 在 dispatch 和 combine 上相较 NCCL 分别取得平均 2.00× 和 1.53× 的加速，并且相较最先进的 MoE 推理框架实现最高 1.66× 的端到端加速。

## Abstract
Expert parallelism (EP) enables inference of large Mixture-of-Experts (MoE) models by placing their experts across multiple GPUs, but requires substantial communication between GPUs at every MoE layer. As contemporary MoE models activate more experts per token, this communication accounts for a growing fraction of inference time. The cost becomes particularly pronounced on PCIe-based consumer GPU systems, where all inter-GPU transfers traverse CPU memory. However, existing MoE-specialized EP communication libraries assume that direct GPU-to-GPU access is available, largely overlooking consumer GPUs. Therefore, most LLM frameworks instead rely on NCCL, whose CPU-staged communication incurs redundant PCIe transfers and competes with expert computation for GPU resources, limiting their overlap. We present ThunderEP, a novel communication design for such systems that removes the relay hops of traditional ring algorithm, moves data through DMA engines to avoid compute resource contention, and minimizes synchronization latency by reducing the polling overhead of completion flags in CPU memory. We integrate the proposed design into vLLM and evaluate it on three widely used MoE models. Experiments on two PCIe systems equipped with RTX 4090 and RTX 5090 GPUs show that ThunderEP achieves average speedups of 2.00$\times$ and 1.53$\times$ over NCCL for dispatch and combine, respectively, and up to 1.66$\times$ end-to-end speedup over state-of-the-art MoE inference frameworks.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：MoE 已成为扩展前沿 LLM 的标准架构，但专家参数往往无法放入单卡，因此需采用专家并行（EP），将专家分散到多张 GPU，并在每个 MoE 层前后各做一次集合通信：dispatch（把 token 发往其选中专家所在 GPU）与 combine（把专家输出送回并归约）。近期模型趋向细粒度专家与更大 top-k（如 DeepSeek-V3 为 256 选 8、Qwen3.8 为 512 选 10），使每个 token 的目的地数增加，通信在推理时间中的占比持续上升。
- **关键矛盾**：现有面向 MoE 的 EP 通信库（DeepEP、Hybrid-EP、pplx-kernels、NCCL EP、NIXL、UCCL-EP）均假设存在 NVLink、GPUDirect P2P 或 RDMA 直连；而 RTX 40/50 系列消费级 GPU 无 NVLink，且 PCIe P2P 被驱动禁用，所有跨卡传输必须经 CPU 内存的 bounce buffer 中转，这些库根本无法运行。
- **现状与代价**：主流 LLM 框架（vLLM、SGLang、Megatron-Core 等）只能回退到 NCCL，而 NCCL 在该场景下存在三大瓶颈：
  - **PCIe 链路争用**：ring 算法多跳中继使同一数据反复穿越 PCIe；实测 RTX 5090 系统单卡 56.5 GB/s，两卡并发时各降至 35.5 GB/s。
  - **SM 争用**：NCCL 通信 kernel 占用 SM，与专家 GEMM 争夺执行资源，限制重叠。
  - **长延迟同步**：无 P2P 时完成标志只能放主机内存，每次轮询都是一次 PCIe 往返。
- **整体含义**：论文针对“被忽视但广泛使用”的 PCIe 消费级 GPU 平台，重新设计 EP 通信路径，把主机内存从“被动中转缓冲区”提升为“共享广播介质”，从而让成本敏感的研究者与中等规模机构也能高效服务大型 MoE 模型。

## 2. 方法论

### 2.1 核心思想与三条设计原则

- 减少通信总量与数据穿越 PCIe 的次数（链路是共享且会争用的）。
- 尽量少占用 SM 资源，使通信能与专家 GEMM 真正重叠。
- 最小化主机内存完成标志的轮询流量与 GPU 间无谓等待。

### 2.2 单步集合通信算法（Single-step Collective）

- **问题**：NCCL ring 在无 P2P 下每一步都是“写主机内存 + 再读回”的往返，且需 N−1 步中继。
- **All-Gather（dispatch）**：每张 GPU 只把自己的 shard 向主机内存写一次，然后各 GPU 直接读回其余 N−1 个 shard；没有任何 shard 在 GPU 间转发，固定两阶段完成。
  - 流量对比：ring 每 GPU 传 2(N−1)S 字节（S 为单卡 shard 大小），ThunderEP 为 N·S 字节；比值为 2(N−1)/N，N=2 时持平，N>2 起开始获益，且随 GPU 数增加优势扩大。
- **Reduce-Scatter（combine）**：数据流为 All-Gather 的逆过程，但需额外求和，论文给出两种归约放置方式：
  - **GPU 归约**：各 GPU 上传 N−1 个块、下载 N−1 个远端块并与本地块相加，流量 2(N−1)S，与 NCCL 解析流量相同，但消除了顺序中继与逐步同步。
  - **部分 CPU 归约**：CPU 先在主机内存对远端块求和，目的 GPU 只下载一个已归约结果再加本地贡献，流量降至 N·S。
  - **实测取舍**：聚合 PCIe 带宽已超过主机 DRAM 带宽，CPU 归约开销大于节省的传输时间，因此最终采用 **GPU 归约**。
