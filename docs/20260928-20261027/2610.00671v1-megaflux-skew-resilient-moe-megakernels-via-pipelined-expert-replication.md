## 摘要
专家混合（MoE）巨型内核将专家并行通信与专家计算融合在一起。然而，在固定专家放置下，路由偏斜会造成 GPU 拖尾：过载的 GPU 决定层延迟，而其他 GPU 则处于空闲状态。复制热点专家可以将工作转移到负载不足的 GPU，但动态副本会引入额外工作：副本必须接收专家权重才能执行；并且在训练期间，其部分权重梯度必须在专家所有者处进行归约。我们提出 MegaFlux，它将专家复制作为运行时决策，并在持久化 MoE 执行中将复制引发的通信流水线化。一个设备端规划器在每个 GPU 的副本预算下，联合选择副本位置并分配按 tile 对齐的 token 块，同时保持路由器输出不变。前向和后向巨型内核实现了流水线化专家复制：副本在所需权重到达时即开始计算，而后向过程将副本梯度归约与正在进行的专家计算重叠。MegaFlux 扩展了 TensorRT-LLM 的 CuTeDSL MegaMoE 前向内核，并引入了新的后向 MoE 巨型内核。在八块 NVIDIA B200 GPU 上，每个方向 147 种配置下，MegaFlux 相较于采用固定放置的相同巨型内核，在前向和后向分别取得 1.45 倍和 1.28 倍的几何平均加速，峰值分别达到 2.14 倍和 2.64 倍。在消融实验中，流水线化在前向隐藏了 56%--76% 的副本权重传输开销，在后向隐藏了 91%--100% 的权重传输与副本梯度归约合计开销；与采用相同复制计划但将这些操作分开执行相比，分别额外带来最高 13.2% 和 26.7% 的层延迟降低。将 MegaFlux 集成到 vLLM 用于 DeepSeek-V4-Pro 预填充时，相较于固定放置，可实现 1.13--1.26 倍的中位端到端加速。

## Abstract
Mixture-of-experts (MoE) megakernels fuse expert-parallel communication with expert computation. However, under fixed expert placement, routing skew creates GPU stragglers: overloaded GPUs determine layer latency while others sit idle. Replicating hot experts can shift work to underloaded GPUs, but dynamic replicas introduce additional work: replicas must receive expert weights to execute and, during training, their partial weight gradients must be reduced at the expert owners. We present MegaFlux, which makes expert replication a runtime decision and pipelines the communication induced by replication within persistent MoE execution. An on-device planner jointly selects replica locations and assigns tile-aligned token blocks under a per-GPU replica budget, leaving router outputs unchanged. The forward and backward megakernels realize pipelined expert replication: replicas begin computation as their required weights arrive, while backward overlaps replica-gradient reduction with ongoing expert computation. MegaFlux extends TensorRT-LLM's CuTeDSL MegaMoE forward kernel and introduces a new backward MoE megakernel. Across 147 configurations per direction on eight NVIDIA B200 GPUs, MegaFlux achieves geometric-mean speedups of $1.45\times$ for forward and $1.28\times$ for backward over the same megakernels with fixed placement, peaking at $2.14\times$ and $2.64\times$. In ablations, pipelining hides $56$--$76$% of replica-weight transfer cost in forward and $91$--$100$% of combined weight-transfer and replica-gradient-reduction cost in backward, yielding up to $13.2$% and $26.7$% additional layer-latency reductions over the same replication plans with these operations executed separately. Integrated into vLLM for DeepSeek-V4-Pro prefill, MegaFlux delivers $1.13$--$1.26\times$ median end-to-end speedups over fixed placement.

# MegaFlux 论文深度总结

## 1. 核心问题与研究动机

- **背景**：MoE（Mixture-of-Experts）已成为 DeepSeek-V3、Qwen3、GLM-4.5、Kimi K2 等大模型的主流扩展范式。专家并行（EP）将专家分散到多 GPU，每个 GPU 只存储部分专家参数，路由后的激活被发送到对应专家所在 GPU 执行。
- **现有方案**：近年出现的 MoE 巨型内核（如 TensorRT-LLM CuTeDSL MegaMoE、FlashMoE、DeepGEMM Mega MoE、Mixture-of-Kittens）把 token 调度、专家计算、token 返回融合进持久化内核，实现通信与计算的细粒度流水线重叠。
- **核心痛点**：巨型内核仍然假设**专家放置固定**——GPU 只能执行自己持有的专家。输入相关的路由偏斜会使热点专家所在的少数 GPU 成为拖尾瓶颈，其余 GPU 空闲。作者在 Qwen3 与 OLMoE 真实路由轨迹上测得：P95 偏斜路由比均衡路由使固定放置 MegaMoE 慢 **7.3%–41.0%**。
- **动态复制的代价**：复制热点专家可把工作迁移到低负载 GPU，但引入两类新通信——副本必须接收专家权重才能执行；训练时副本产生的部分权重梯度必须在专家所有者处归约（如 UltraEP 在 forward dispatch 前分发权重、backward 后聚合梯度）。
- **核心挑战**：如何把复制引发的权重传输与梯度归约**融入 MoE 巨型内核已有的细粒度通信–计算流水线**，而不是作为独立阶段围绕内核执行。

## 2. 方法论

### 2.1 总体思想
MegaFlux 将专家复制变为**运行时决策**，由设备端规划器生成 block 粒度的副本放置与 token 块分配方案，并由前向/后向持久化巨型内核**流水线化执行**复制带来的权重传输与梯度归约，同时保持路由器输出（专家选择、路由权重、token 数）完全不变，避免质量损失。

### 2.2 规划器：副本放置与 token 块分配（§3.1）
- **分块建模**：将每个专家的路由行按每块最多 β=128 行切分为 token 块，块数 $b_e=\lceil c_e/\beta\rceil$，保证每个专家至多一个不完整块，避免复制带来的 padding 开销。同一分配同时决定 DGrad 行归属与 WGrad 部分块贡献者。
- **优化目标**（式 3）：以块数作为计算负载代理，最小化最大 GPU 负载 $\max_r \ell_r$，约束为每专家块数守恒、每 GPU 远程副本数不超过预算 $s$：
  $$\min_{q\ge 0}\ \max_r \sum_e q_{er}\quad \text{s.t.}\ \sum_r q_{er}=b_e,\ \sum_{e:h(e)\ne r}\mathbf{1}[q_{er}>0]\le s$$
- **有界贪心搜索**：并行运行 4 个贪心搜索，均从无复制方案出发，把过载 owner 的块迁往目标负载 $\tau=\lceil\sum_e b_e/P\rceil$，优先复用已有副本、再在最低负载的合格 GPU 上开新副本。4 个候选由「供体优先级（总过载下降 vs 最大剩余 home-expert 负载）」×「扇出（每轮每专家至多一个新副本 vs 多副本）」组合而成；每轮每个过载 owner 访问一次，搜索在 $s+2$ 轮或无移动时停止。
- **精化**：选最大负载最小的候选（并列时副本数少者优先），剪除冗余副本，再做不增加最大负载的单块迁移。
- **反向 reduction-aware 变体**：剪枝阶段使用代理 $\max_r(\ell_r+\lambda n_r)$，其中 $n_r$ 为 GPU r 所拥有专家的远程副本数，固定 $\lambda=12$（相当于每远程副本折算 12 个 token 块的 owner 侧归约开销）；若剪枝后代理未严格优于无复制方案则回退。反向复用前向选定的计划，规划开销只计一次。
- **块到路由映射**：按源 GPU、局部 (token, top-k 位置) 稳定排序后切块，保证 token 身份、top-k 位置与路由权重保留，副本梯度回到 owner 归约。

### 2.3 执行器：流水线化专家复制（§3.2）
- **前向**：利用「FC1 只需 $W_1$ + 输入块，FC2 只需 $W_2$ + FC1 激活块」的**分阶段权重就绪**，使副本 FC1 与 $W_2$ 传输重叠，同时 owner 专家计算与任一传输重叠；操作数加载器在既有 tile 调度内执行这些条件，无需副本级全局 barrier。副本权重传输**复用通信 warp**：少量 warp 从内核入口即服务副本权重队列，其余输入传输 warp 先排空 token 块再加入，随执行推进逐步增加可用资源。
- **反向**：DGrad 先消费 $W_2$ 再消费 $W_1$，按相反顺序应用同样的分投影就绪，使两次传输都与 DGrad 重叠。MXFP8 反向需为 WGrad 准备 token 轴的 $D_e$ 与 $dZ_e$ 重量化（DGrad 与 WGrad 归约维度不同），该转换被调度到原本空闲的通信间隔；worker 在退役上一累加器状态后独立从 DGrad 转入 WGrad，避免设备级阶段 barrier。
- **梯度归约流水线**：仅提前产出一个部分不够，owner 必须等所有参与 GPU 的对应梯度 tile 部分就绪。MegaFlux 因此在所有参与 GPU 上**优先为复制专家准备 WGrad 并生产梯度 tile**；owner 侧 worker 一旦所需部分齐备，即按固定顺序以 FP32 拉取并累加，与其他 tile 的计算重叠，从而把完整归约依赖提前并流水化。
- **实现基础**：扩展 TensorRT-LLM CuTeDSL MegaMoE 前向内核，并**新增后向 MoE 巨型内核**；面向 Blackwell，使用 tcgen05 MMA、TMEM 中 FP32 累加、原生块缩放 MMA 支持 MXFP4/MXFP8、双 CTA MMA 与运行时 MMA token 维度降低 padding，TMA 搬运算子。
