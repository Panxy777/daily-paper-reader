## 摘要
部署混合专家（MoE）模型高度依赖专家并行，这会产生密集的 GPU 间通信。因此，最先进的推理系统需要数据中心 GPU 具备高带宽、点对点互连（如 NVLink）来处理海量 token 路由，导致部署成本高得难以承受。消费级 GPU 以显著更低的成本提供相当的计算能力，有望让 MoE 推理惠及个人，并支持隐私保护的本地部署。然而，其带宽受限（仅有较弱的 PCIe 总线带宽）且由主机中转的互连（不支持 P2P）会引入严重的通信瓶颈。我们提出 CoMoE，一种通信高效的 MoE 推理系统，通过新颖的以主机为中心的路由方式解决这一不匹配问题。我们的关键洞察是，独特的通信拓扑提供了将主机提升为主动路由枢纽的机会，从而能够从根本上减少通信量并消除全局同步引发的停顿。具体而言，对于 token 分发，我们引入由主机支持的 token 多播，将共享 token 仅写入主机一次，从而消除出站传输冗余。对于 token 合并，我们提出一种使用主机暂存缓冲区的细粒度、token 级聚合机制，取代僵化的全局同步并缓解长尾效应。在 RTX 5090 GPU 上的评估表明，CoMoE 将推理吞吐量最高提升 1.46 倍，仅以 23.4% 的硬件成本接近支持 NVLink 的 A800 GPU 的性能。

## Abstract
Deploying Mixture-of-Experts (MoE) models relies heavily on Expert Parallelism, which generates intense inter-GPU communication. Consequently, state-of-the-art inference systems require high-bandwidth, P2P interconnects (e.g., NVLink) in datacenter GPUs to handle massive token routing, making deployment prohibitively expensive. Consumer GPUs offer comparable compute power at significantly lower cost, promising to democratize MoE inference for individuals and enable privacy-preserving local deployments. However, their bandwidth-limited (only weak PCIe bus bandwidth) and host-mediated interconnects (no P2P support) introduce severe communication bottlenecks.   We present CoMoE, a communication-efficient MoE inference system that resolves this mismatch through novel host-centric routing. Our key insight is that the unique communication topology provides the opportunity to elevate the host to an active routing hub, which can fundamentally reduce communication volume and eliminate global synchronization-induced stalls. Specifically, for token dispatch, we introduce host-backed token multicast to write shared tokens to the host exactly once, eliminating outbound transmission redundancy. For token combine, we propose a fine-grained, token-level aggregation mechanism using host staging buffers, which replaces rigid global synchronization and mitigates straggler effects. Evaluation on RTX 5090 GPUs shows that CoMoE improves inference throughput by up to 1.46x, approaching the performance of NVLink-capable A800 GPUs at only 23.4% of the hardware cost.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：现代 MoE 模型（如 DeepSeek-V2、Qwen3、GLM-4.7）参数规模巨大，专家数量常达 64–128 个，必须借助专家并行（Expert Parallelism, EP）分布到多 GPU 上。EP 在每层 MoE 中都会触发 **dispatch（token 路由到专家）** 与 **combine（聚合专家输出）** 两次 All-to-All 通信。
- **问题**：主流系统（SGLang、DeepEP、PPLX 等）依赖数据中心 GPU 的 NVLink/NVSwitch 高带宽 P2P 互连，部署成本极高。
- **消费级 GPU 的机会与困境**：RTX 5090 的算力（FP16 419 TFLOPs）和内存带宽（1.8 TB/s）与 A800 相当，价格却仅约 1/6；但它**仅有 PCIe 5.0 x16（约 64 GB/s）、无 P2P 支持、所有跨 GPU 流量需经主机 DRAM 中转**。
- **量化证据**：作者以 SGLang 为基线实测，消费级 GPU 上延迟最高增加 1.97×；在 prefill 长度 2048 时，**通信占总执行时间的 81.6%**（A800 仅 44.8%）。
- **根因分析（两个放大因素）**：
  - **分发冗余**：一个 token 平均被路由到 2.98–5.37 个不同 GPU（如 Qwen3-30B-A3B 为 5.37），All-to-All 会向每个目的 GPU 重复发送同一 token，在 PCIe 上造成出站带宽放大。
  - **粗粒度同步**：All-to-All 是 bulk 操作，需等待最慢 peer，实测 combine 阶段 stall 可达 301 µs（占 combine 的 11.9%），无法用通信-计算重叠掩盖长尾效应。
- **整体含义**：论文主张消费级 GPU 的“主机中转、集中式拓扑”不应被视为缺陷，而应被重新利用为架构优势，从而在低成本硬件上实现接近数据中心级别的 MoE 推理性能。

## 2. 方法论：核心思想与关键技术细节

### 2.1 核心思想
- 将主机（CPU + DRAM）从**被动的 bounce buffer** 提升为**主动的集中式路由枢纽**，围绕主机重新设计 dispatch 与 combine 两个阶段。

### 2.2 分发阶段：Host-Backed Token Multicast（零冗余分发）
- **视角转换**：把 MoE dispatch 从“All-to-All”重新建模为“token 级 one-to-many multicast”。
- **理论分析**：设总专家数 $E$、每 token 激活 $k$ 个专家、GPU 数 $G$，均匀无放回选择下，单 token 平均目的 GPU 数为：
  $$E[N_{dst}] = G\left(1 - \frac{\binom{E - E/G}{k}}{\binom{E}{k}}\right)$$
  当 $E=64,k=4$ 时约 3.38；$E=128,k=8$ 时约 5.34。
- **三步流程**：
  1. **Metadata broadcast**：发送方按目标 rank 生成索引数组，指明各接收 GPU 应拉取哪些 token。
  2. **Zero-redundancy write**：每个待发送 token **仅写入主机内存一次**（而非每个目的写一次）。
  3. **Parallel pull**：各目的 GPU 依据索引数组，从主机同一份副本并行拉取。
- **效果**：出站压力按 fanout 比例下降，带宽压力从瓶颈的发送端转移到接收端聚合的 host→GPU 读带宽。

### 2.3 合并阶段：Decomposed Fine-grained Combine via Host Staging
- **关键论点**：token $i$ 的重建只依赖其被分配专家的贡献，**不需要全局 collective 完成**；MoE 的最小同步单元是 token，而非 batch。
- **拆解 All-to-All**：把 collective 拆为独立的**单向写（producer 存入）** 与**单向读（consumer 取出）**，通过主机侧 ready flag 与 per-token 完成状态协调，发送方与接收方不再 lockstep。
- **Fused Transfer Kernel**：将线程块专门化为 sender/receiver 两类角色，用 `cudaLaunchCooperativeKernel` 融合，以饱和 PCIe 双向带宽。
- **Pipelined reduction**：每 token 维护未完成 rank 贡献计数器，计数归零即触发该 token 的最终累加，实现“部分 token 的通信尾部”与“另一部分 token 的计算”重叠。
- **NUMA-aware staging buffer placement**：强制发送 GPU 直接写入**接收方本地 NUMA 域**的暂存缓冲，使发送走高效远程写、接收走低延迟本地读，并减少 PCIe 读请求事务。
- **两项优化**：
  - **Tiled transfer**：按 per-token 数据大小把线程块划分为多个 thread tile，避免隐藏维度无法整除导致的 SM 空闲。
  - **Batched commit**：同一 block 内多个 thread tile 共享 commit 状态，批量提交，摊薄 per-token 就绪信号开销。

### 2.4 实现要点
- 作为 SGLang 的新 MoE 通信后端接入，模型代码与调度器不变，通过配置切换。
- 暂存缓冲用 `cudaHostRegister` 固定并映射进所有 GPU 地址空间，GPU 直接 load/store，**无 cudaMemcpy、无 CPU 线程在数据路径上**。
- 主机内存开销：Qwen3-30B-A3B 约 512 MiB/GPU（8 GPU 共 4 GiB），GPT-OSS-20B 约 720 MiB/GPU（共 5.6 GiB），均 < 0.5% 的 1.5 TB DRAM。
- SM 占用：PCIe 带宽约 24 SM 即饱和，故启动 48 个 512 线程 block，占 170 SM 中的 24 个（14.1%）。

## 6. 主要结论与发现

- **通信是消费级 GPU 上的主导瓶颈**：prefill 2048 时通信占 81.6%，计算时间与 A800 相当。
- **CoMoE 显著降低通信开销**：prefill 通信延迟平均降低 55.7%，通信/计算比从 >4.6× 降至约 2.25×（2.17× 改善），A800 NVLink 约为 0.8×。
- **Dispatch 加速**：Qwen3-30B-A3B 从 1789.7 µs 降至 1065.6 µs（1.68×），GLM/DeepSeek/GPT-OSS 分别为 1.40×/1.54×/1.96×；且 CoMoE 的 dispatch 延迟对激活专家数不敏感（仅由隐藏维度决定）。
- **Combine 解耦有效**：相对 CoMoE-Sync，Qwen3 提升 13.2%、GLM 提升 11.2%、DeepSeek 4.9%、GPT-OSS 8.1%，验证长尾掩盖效果。
- **端到端性能**：吞吐最高提升 1.46×（GPT-OSS），Qwen3 1.41×、DeepSeek 1.29×、GLM 1.24×；TTFT 平均降 18.8%、TPOT 平均降 26.9%。
- **逼近数据中心**：达到 A800 NCCL 吞吐的 89.7%–98.8%（GLM 差距仅 1.2%），达到 A800 DeepEP 的 85.3%–90.0%。
- **成本优势**：匹配 A800 DeepEP 吞吐仅需 18.5%–23.4% 的硬件成本；Tokens/$ 比为 4.27×–4.50×。
- **真实场景**：DeepResearch 任务中位延迟从 29.23 s 降至 25.41 s（−13.1%），P90 从 54.36 s 降至 49.14 s（−9.6%）。

- **集成方式友好**：以 SGLang 的 MoE 通信后端形式接入，模型定义、调度器与前端接口均不改动，仅通过配置切换，迁移成本低，具备被上游采纳的现实路径。
- **资源开销可预期**：给出明确的每卡主机内存占用（512–720 MiB）与 SM 占用（170 SM 中约 24 个，14.1%），便于部署者做容量规划；SM 占用基于“约 24 SM 即饱和 PCIe 带宽”的实测标定，具备一定通用性。
- **数据路径干净**：`cudaHostRegister` + 统一地址映射，GPU 直接 load/store，避免 `cudaMemcpy` 与 CPU 线程介入，降低了实现复杂度与额外拷贝开销。
- **未明确的部分**：论文摘要式总结中未见公开代码仓库、复现脚本或端到端配置文件的说明；主机侧暂存缓冲的分配策略、NUMA 绑定方式的具体参数未展开，第三方独立复现可能需要额外调优。

## 10. 对领域的启示与可延伸方向

- **“缺陷即特性”的系统设计范式**：把 PCIe-only、无 P2P、主机中转这些被默认视为劣势的约束，重新表述为“集中式多播 + 解耦同步”的设计前提，为低成本集群上的大模型推理提供了不同于“追赶 NVLink”的技术路线。
- **同步粒度的再思考**：以 token 为最小同步单元、把 collective 拆为单向写与单向读，这一思路并不局限于 MoE，原则上可迁移到其它存在“部分依赖即可推进”的集合通信场景（如部分专家并行、稀疏注意力的跨卡聚合）。
- **可能的后续工作**：跨节点扩展（主机枢纽 + RDMA 分层）、与低精度通信的联合设计、自适应策略（按 fanout 与 batch 形态在 All-to-All 与主机多播之间动态选择）、以及在训练反向传播场景下的适用性验证。
- **实践意义**：若结论在更多硬件与规模上成立，将显著降低中小团队部署大规模 MoE 服务的硬件门槛，把“能否用消费级卡跑 MoE”从可行性问题推进到性价比问题。

## 11. 总体评价

论文选题切中真实的部署痛点：在算力已不再是消费级 GPU 短板的当下，互连成为唯一的结构性瓶颈。作者没有选择在既有 All-to-All 框架内做增量优化，而是依据对瓶颈的实测归因（分发冗余 + 粗粒度同步），重新设计了 dispatch 与 combine 两个阶段的通信语义，并用理论 fanout 模型、受控基线（CoMoE-Sync）与逐项消融支撑其主张。实验在 4 个架构差异明显的 MoE 模型上、跨消费级与数据中心两套硬件展开，指标体系覆盖微基准、系统吞吐/延迟、成本效益与真实 agent 任务，论证链条较为完整；在吞吐逼近 A800 NCCL 89.7%–98.8%、成本降至 18.5%–23.4% 的同时，给出了可解释的机制而非纯经验调参。

主要保留在于外部效度：单节点、单一消费级 GPU 型号、以 prefill 为主的负载画像，使得“主机作为多播枢纽”的收益边界尚不清晰；鲁棒性与多节点扩展的讨论也相对简略。总体而言，这是一篇问题定位清晰、机制解释充分、工程落地完整的推理系统工作，其核心洞见（把主机从 bounce buffer 提升为主动路由层、把 MoE 同步粒度下沉到 token）具有超出本文具体实现的参考价值。
