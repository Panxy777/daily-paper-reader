## 摘要
随着混合专家（MoE）模型规模持续扩大，其服务越来越依赖于在日益增多的设备上采用专家并行（EP）。然而，专家工作负载的偏斜会在计算、通信和内存之间造成不均衡，使负载均衡成为分布式 MoE 服务的核心优化目标。我们观察到，均衡并非没有代价：为平衡某一维度而引入的操作本身可能开销高昂或造成不均衡。这促使我们重新思考均衡：将其视为约束而非优化目标。我们提出 Zepp，它在对物理资源（即 GPU 和 NIC）施加简化平衡约束的前提下，直接优化分布式 MoE 服务中的瓶颈通信。Zepp 在放置、路由和执行层面逐步优化节点间通信。它首先在 GPU 约束下放置专家副本以减少 token 通信，然后在 NIC 约束下通过拆分与合并原语重塑通信流，最后对专家计算进行划分与调度，以重叠由此产生的通信。为适应动态工作负载，Zepp 在每次迭代中联合协调计算、token 通信和专家权重移动。这些设计共同使 Zepp 能够追求最高效的执行，而非单一维度上的均衡执行。我们实现了 Zepp，并将其与 7 个最先进的 MoE 服务系统进行评估，相较于最快的竞争基线，实现了最高 6.68× 的 MoE 层加速和 1.86× 的几何平均加速。

## Abstract
As Mixture-of-Experts (MoE) models continue to scale, serving them increasingly relies on expert parallelism (EP) across a growing number of devices. Yet skewed expert workloads create imbalance across computation, communication, and memory, making load balancing a central optimization objective in distributed MoE serving. We observe that balance is not free: operations introduced to balance one dimension can themselves be expensive or imbalanced. This motivates us to rethink balance as a constraint rather than an optimization objective. We present Zepp, which directly optimizes the bottleneck communication in distributed MoE serving subject to simplified balance constraints on physical resources, i.e., GPUs and NICs. Zepp progressively optimizes inter-node communication across placement, routing, and execution. It first places expert replicas to reduce token communication under GPU constraints, then reshapes communication flows through split and merge primitives under NIC constraints, and finally partitions and schedules ex- pert computation to overlap the resulting communication. To adapt to dynamic workloads, Zepp jointly coordinates computation, token communication, and expert-weight movement at each iteration. Together, these designs allow Zepp to pursue the most efficient execution rather than a single-dimension balanced one. We implement Zepp and evaluate it against 7 state-of-the-art MoE serving systems, achieving up to 6.68$\times$ MoE layer speedup and a geometric mean speedup of 1.86$\times$ over the fastest competing baseline.

## 2. 方法论：Zepp 系统设计

- **核心思想**：按“避免通信 → 重塑通信 → 隐藏通信”三阶段渐进优化，并在每次迭代联合协调计算、token 通信与专家权重移动。
- **阶段一：专家复制、放置与局部优先路由（GPU 约束下）**
  - 每 GPU 预留 R 个额外专家槽位（实验中 R=2），按历史 token 需求贪心选择复制对象，每次复制后更新每副本需求，直至槽位填满。
  - 分层放置：先跨节点轮询分散同一专家的副本以扩大**节点级覆盖**，再在节点内按预期计算负载分配到各 GPU；放置跨 batch 复用，避免反复搬运权重。
  - 路由建模为整数规划（式 1）：最小化 Σ a_ij·M^e_ij（a_ij 为 GPU i→j 的逆带宽），约束为①保持模型原始专家选择（行和固定）；②每个副本负载 |Σ_i M^e_ij − q^e_j| ≤ C·q^e_j，其中 q^e_j 为均分参考负载，C 为松弛比例，同时约束单 GPU 总负载；③非负整数。
  - 实现上用贪心注水（优先本 GPU → 同节点 → 远程）构造可行解，再做贪心精化，把同一 token 的远程请求合并到更少节点。
- **阶段二：Split 与 Merge 重塑通信 + 重叠调度（NIC 约束下）**
  - **Split**：把 all-to-all 拆成按源/目的节点可独立调度的 send-recv 流，显式控制每条流走哪个 NIC；当某 GPU 出流量过大时，把超出部分经 NVLink 转移到同节点其他 GPU 的 NIC 发出。优化式（2）：最小化节点内搬移成本 Σ c_ij x_ij，约束各 NIC 负载 ≤ (1+C_NIC)·V/G；式（3）给出 C_NIC=0 时最小搬移量 = ½Σ|V_i − V/G|。
  - **Merge**：dispatch 时，同一 token 被同节点多个专家选中，则跨网只传一次，再由接收 GPU 经 NVLink 转发（消除冗余跨节点 payload）；combine 时专家输出不可去重，改为先在节点内预归约（pre-reduce）成部分和，再一次性传回源节点。同时合并同路径小流以摊薄消息启动延迟。
  - **互补流水调度（算法 1）**：dispatch 阶段“通信驱动计算”——流按节点对轮次推进，某计算组输入齐备即执行，计算顺序跟随投递顺序而非专家编号；combine 阶段“计算驱动通信”——按 token 源节点分组（returnGroup[d]）调度专家计算，使完整返回组尽早就绪，尽早预归约并启动回传，与后续组计算重叠。
- **阶段三：三流调度下的节点内专家交换（动态适配）**
  - 当历史放置不再满足 GPU 负载约束时，不做全局重映射，只在**同一节点内**交换两个专家副本的物理位置（式 4：最小化最大 GPU 负载，S 仅含节点内交换），保持槽位占用与节点级专家覆盖不变，只产生节点内权重移动。
  - 交换仅在负载不均衡超阈值且能降低最大负载时触发；权重可用性被纳入 §4.2 的依赖调度，计算组需同时满足“输入 token 到达”和“专家权重就绪”，用无关专家的计算填补权重搬运窗口，无需全局同步屏障。
- **实现要点**：C++/CUDA + Python 绑定，CUTLASS grouped GEMM，NVSHMEM 做跨节点 RDMA，CUDA stream 协调；dispatch 采用 union forwarding（接收节点把完整 token 转发给本节点所有 GPU，GEMM 用 gather 索引取行）；对称暂存缓冲区初始化时分配并复用；路由、交换规划与元数据开销约占迭代延迟 5%。

## 6. 主要结论与发现

- **性能**：相对 A2AV+GEMM 加速 2.10–6.68×；相对每个配置下最快竞争基线几何平均 **1.86×**，最高 2.78×。
- **节点越多、负载越大收益越明显**：16 MB 下相对 COMET+EPLB，4→16 节点加速从 1.34× 升至 3.53×（Qwen）、1.23×→2.94×（K2），说明减少远程流量比“重叠全部稠密 all-gather”更有效。
- **小负载下避免远程通信价值高**：16 节点 1 MB 时对 A2AV+GEMM 达 6.68×（Qwen）/5.77×（K2）。
- **弱扩展**：1 MB 在 32 节点达 9.49×（A100）/15.10×（H100），因额外槽位随规模增多、放置与路由灵活性提升；64 MB 稳定在 2.35–2.93×（A100）/2.46–4.13×（H100）。
- **端到端**：prefill 吞吐提升 1.32×→1.92×，decode 加速 1.04×→1.57×（1→16 MB），证明 MoE 层优化在含 attention 的完整服务中仍有意义。
- **消融**：重叠调度单独贡献 1.12×（Prof. law）/1.05×（rotating）；加入放置与路由升至 1.25×/1.07×；交换重叠再提升 1.9%/3.0%。需求未出现在历史中时，节点内交换贡献更大。
- **总体结论**：放松均衡约束、直接优化瓶颈通信，可避免“平衡一维、恶化另一维”的循环，是一条更优的分布式 MoE 服务优化路径。

## 8. 局限与可质疑之处

- **均衡松弛约束的引入是有代价的**：Zepp 用 C（副本负载松弛比例）与 C_NIC 显式允许不均衡，并靠复制专家（R=2）换取路由灵活性。这意味着**额外显存与额外权重副本**是前提成本，论文未系统报告 R 增大（如 R=4/8）时的显存开销、权重搬运总量与收益饱和点，也未与“更大 R 的复制基线”做同预算对比，因此“复制+松弛”相对纯复制方法的增益边界不够清晰。
- **依赖历史 trace 的假设较强**：复制对象选择、放置与路由规划均基于历史 token 需求分布。论文用 “Prof. law only” 与 “rotating” 两种场景做了敏感性分析，但对**分布突变**（如新领域流量突然涌入、路由策略切换、长尾突发）的鲁棒性只有定性讨论与一次 rotating 实验，缺少突变幅度/切换频率的定量刻画，也未给出历史窗口长度的影响。
- **交换触发阈值缺少敏感性分析**：节点内交换的触发条件（不均衡超阈值且能降低最大负载）中阈值取值、交换频率与收益关系未做扫描；交换本身引入的权重搬运与依赖等待在不同阈值下的权衡不明。
- **评测负载为合成重采样**：trace 来自公开 MoE 层记录并按 top-k 有放回采样到目标规模，**丢失了真实请求的时序相关性、batch 内 token 语义分布与真实到达过程**；端到端实验虽用 SGLang 集成，但负载规模仅 1/4/16 MB 三档，未覆盖真实在线混合（prefill/decode 交织、变长序列、KV cache 压力）。
- **基线实现公平性存在不确定性**：A2AV+GEMM 为作者自实现，FAST、COMET、EPIC、MoonEP 等为复现或近似配置；复制类基线虽统一 R=2，但各系统原始设计假设（如是否假设均匀专家、是否支持多 NIC 显式路由）不同，绝对加速比可能混入实现质量差异。论文以“每个配置下最快竞争基线”的几何平均（1.86×）作为主指标是较稳妥的处理，但单点最高 2.78×、6.68× 等数字应谨慎解读。
- **拓扑与硬件覆盖偏窄**：所有实验为“每节点 4 GPU + 每 GPU 一 NIC”的同构胖树式 Slingshot 互联，未涉及**多 NIC per GPU、非对称带宽、跨机架/跨域层级网络、NVLink 域更大的 8-GPU 节点**等情形；split 的 NIC 重分配与 merge 的节点内预归约在这些拓扑下的收益结构可能显著变化（尤其 8-GPU 节点会削弱“跨节点通信是瓶颈”的前提）。
- **仅覆盖推理服务，未涉及训练**：MoE 训练同样存在 all-to-all 与负载偏斜，但存在反向传播、激活重计算、优化器状态与专家权重更新的额外约束，Zepp 的三阶段（尤其节点内交换与权重搬运）能否迁移未讨论。
- **系统开销报告较粗**：路由、交换规划与元数据开销“约占迭代延迟 5%”为总体估计，未按阶段（式 1 的整数规划求解时间、式 2 的流规划、交换求解）拆分，也未给出规划算法在更大专家数（如 512+）或更细粒度流数下的**扩展性曲线**；贪心注水+精化的解质量相对最优整数解的差距未量化。
- **缺少与“均衡目标”类方法的理论对比**：论文的核心论点是“均衡不是免费”，但主要以时间线 case study 与端到端数字支撑，未给出形式化论证（例如在给定带宽/算力模型下，松弛均衡相对严格均衡的最优性条件），因此“何时应松弛、松弛多少”仍偏经验（C、C_NIC 的选取依据不足）。

## 9. 启发与可延伸方向

- **优化目标的重新表述**具有普适方法论价值：把多维资源的“均衡”降级为约束、直接优化端到端关键路径瓶颈，这一思路可迁移到**稠密模型 EP/TP 混合并行、MoE 训练、以及异构集群（GPU+NIC+NVLink 混合瓶颈）**的调度设计中。
- **Split 与 Merge 的双向粒度控制**提示：对不规则稀疏流量，单纯“拆分打散”会放大消息数量与启动延迟，需配套“合并去重 + 节点内预归约”，这一对操作可作为 MoE 通信库的通用原语。
- **Dispatch 与 Combine 依赖方向相反**的观察可直接推广为流水调度的一般原则：**上游多对一（dispatch）适合通信驱动、下游一对多汇聚（combine）适合计算驱动**，可指导其他 all-to-all 场景（如序列并行、专家并行的反向传播）。
- **节点内交换替代全局重映射**是一种“局部修复”范式：在保持全局不变量的前提下，仅用低成本局部操作吸收动态漂移，适合作为长期运行服务的在线自适应机制。
- **可延伸的具体工作**：①对 C、C_NIC、交换阈值、R 做联合敏感性分析与自动调参；②引入在线分布漂移检测与历史窗口自适应；③在 8-GPU 节点、多 NIC per GPU、层级网络上验证；④扩展到 MoE 训练的反向 all-to-all；⑤将规划求解从贪心升级为近似最优（如 LP 松弛 + 舍入）并报告解质量差距。

## 10. 总体评价

Zepp 是一篇**问题洞察优先、系统实现完整**的 MoE 推理服务系统论文。其最大贡献不在于某个单点技术，而在于**重新定义了优化目标**：用图 3 的时间线证据说明“为均衡而做的操作本身会制造新的不均衡”，进而把均衡降为松弛约束，围绕节点间通信这一真实瓶颈组织“避免—重塑—隐藏”三阶段协同设计。三阶段各自对应清晰的约束形式（式 1–4），且工程落地度高（GPU 端规划、无逐层主机同步、规划开销约 5%、代码开源）。

在评估上，论文覆盖两模型、多节点规模、两代 GPU、单层与端到端、消融与时间线，基线数量与组合较充分，主指标采用“最快竞争基线几何平均”也较为克制。主要不足集中在**对历史分布假设的鲁棒性验证不足、复制预算（R）与松弛参数（C、C_NIC）缺少敏感性分析、拓扑覆盖偏窄（仅 4-GPU 节点 + 单 NIC）、负载为合成重采样**，以及部分基线为自实现/近似复现带来的公平性不确定性。

综合而言，论文的核心论点（均衡不是免费的，应直接优化瓶颈通信）**论证充分且具有迁移价值**；其定量加速比（几何平均 1.86×、最高 2.78×、弱扩展至 128 GPU）在给定实验条件下可信，但外推到更异构网络与真实在线负载时需谨慎。作为 MoE 服务系统方向的工作，它为后续“以瓶颈为中心”的调度设计提供了清晰的框架与可复用的工程基线。
