## 摘要
随着混合专家（MoE）模型扩展到数百个专家以及更高的 top-k 路由，分布式训练中的内存效率成为关键瓶颈。峰值内存主要由 MoE 块而非注意力主导：MoE 分发流水线中的每个中间缓冲区都会随 top-k 路由单独扩展。标准的 all-to-all 分发器在单个集合通信步骤中发送所有被路由的 token，这要求一次性构造完整的 top-k 扩展缓冲区。在本工作中，我们提出 RelayMoE，一种基于环的 MoE 执行模型，它在专家权重或 token 循环时进行本地计算，从而避免完整的 top-k 扩展分发缓冲区。RelayMoE 根据通信量在专家路由与 token 路由之间选择，并将传输与计算重叠。环结构天然支持反向传播期间内存高效的 MoE 重计算：每一跳重建专家中间结果，用其计算梯度，并在下一跳之前释放。节省的内存可支持更长序列和更大批量，或保留更多注意力激活以减少注意力重计算并提高训练吞吐量。我们在 30B-57B 生产级 MoE 模型及多种专家配置上评估 RelayMoE。在单层 MoE 实验中，RelayMoE 相比 Megatron-LM 取得平均 2 倍加速。在相同 GPU 内存预算下的全模型训练中，它将吞吐量最高提升至 2.02 倍，并将最大可测试可训练序列长度最高扩展至 2.85 倍。

## Abstract
As Mixture-of-Experts (MoE) models scale toward hundreds of experts and higher top-$k$ routing, memory efficiency in distributed training becomes a critical bottleneck. Peak memory is dominated by the MoE block, not attention: every intermediate buffer in the MoE dispatch pipeline is individually scaled by top-k routing. The standard all-to-all dispatcher sends all routed tokens in a single collective step, requiring the full top-$k$-expanded buffer to be constructed at once. In this work, we propose RelayMoE, a ring-based MoE execution model that computes locally as expert weights or tokens circulate, avoiding full top-$k$-expanded dispatch buffers. RelayMoE selects between expert and token routing according to communication volume and overlaps transfers with computation. The ring structure naturally supports memory-efficient MoE recomputation during backward: each hop reconstructs expert intermediates, uses them to compute gradients, and releases them before the next hop. The saved memory supports longer sequences and larger batches, or retains more attention activations to reduce attention recomputation and improve training throughput. We evaluate RelayMoE on 30B$-$57B production MoE models and varied expert configurations. In single-layer MoE experiments, RelayMoE achieves a $2\times$ average speedup over Megatron-LM. In full-model training under the same GPU memory budget, it improves throughput by up to $2.02\times$ and extends the largest tested trainable sequence length by up to $2.85\times$.

## 1. 核心问题与整体含义（研究动机与背景）

- **MoE 规模化带来的内存瓶颈**：前沿 MoE 模型正沿多个维度同时扩张——专家数（8→512）、top-k（2→10）、序列长度（32K→262K）、专家 FFN 宽度。表 1 显示，调度缓冲区相对基础激活的膨胀倍数从 2× 增至 10×，MoE 调度峰值内存十年间增长约一个数量级。
- **峰值内存由 MoE 块而非注意力主导**：作者用 Qwen3 风格模型（top-8、micro-batch 24、序列 16384、8×H100）做 profiling，发现每个 MoE 块在前后向都产生尖锐内存尖峰（最高 51 GB，块间仅约 14 GB）。单层中每个 top-k 扩展调度张量约 2.6 GiB，是 336 MiB 基础激活的 8×，多个此类张量共存导致反向每层峰值超 42 GB。
- **根因**：标准 all-to-all 分发器必须在一次集合通信前构造完整的 top-k 扩展缓冲区（`[tokens×k, H]`），且 dispatch/combine 流水线中各阶段新输出与旧输入共存，使每个中间缓冲区都被 top-k 单独放大。
- **现有工作的不足**：DeepEP、HybridEP、NCCL-EP 优化了调度吞吐与延迟；Tutel、FasterMoE、Janus 侧重通信效率或专家拉取，但 MoE 执行（尤其反向）的峰值显存问题未被根本解决。
- **整体含义**：需要重新设计 MoE 块中通信与计算的组织方式，从"先聚合再计算"转为"边流动边计算"，以解除 top-k 与 EP 度对显存占用的乘性放大。

## 2. 方法论

### 2.1 核心思想
- **环形执行模型**：将专家权重或 token 激活在 EP 组的 N 个 GPU 上以环的方式逐跳传递，每跳用本地数据与到访分区做部分计算并就地累加，N 跳后所有分区访问过所有 GPU，输出完整。
- **内存上界**：任一 GPU 只需持有本地数据、输出/梯度累加器、当前与预取分区及其通信缓冲，显存占用与 top-k 因子和 EP 度解耦，且天然支持 dropless、无 padding 的专家计算。
- **数学等价性**：每个 token–expert 对使用相同权重与路由概率做相同 GEMM，仅执行顺序不同（all-to-all 先聚合后算，RelayMoE 逐跳累加），故结果等价。

### 2.2 关键技术细节
- **前向跳**：用路由图找出选中到访专家的本地 token，本地 permute 后执行专家 GEMM，按路由概率加权并累加进运行中的输出激活；未匹配的 token 跳过。
- **反向跳**：token 输入、输出梯度、路由概率梯度保持本地；专家权重梯度在复用通信缓冲中跨 rank 求和，并"滞后一跳"随对应权重返回所有者（首跳只传权重，末跳为纯梯度回传）。
- **通信–计算重叠**：
  - 前向：计算当前分区时异步 P2P 预取下一分区权重，使每跳时间趋近 max(计算, 传输) 而非二者之和。
  - 反向：本地部分权重梯度无需等待入站梯度缓冲即可先算，随后同步、就地累加并异步转发；每跳传输合并权重与累积梯度。
- **自适应路由（专家 vs token）**：两种模式结果相同但通信量不同。表 2 给出每跳通信量与驻留内存公式：
  - 专家路由：前向传 `E_local×W`，反向传 `2×E_local×W`，token 驻留；
  - token 路由：前向传 `B×S×(H+M)`，反向传 `2×B×S×(H+M)`，专家驻留；
  - 在 SP/CP/ETP 下分别调整为 `E/EP×W/ETP` 与 `B×S/(SP×CP)×(H+M)`。
  - 训练开始时按完整并行配置估算两种模式的每跳通信量，选较小者；专家权重相对 token 大时倾向 token 路由，反之倾向专家路由。
- **内存高效 MoE 重计算**：反向每一跳用保存的本地 token/路由信息与到访专家分区重建中间量（R），立即计算并累加梯度后释放，再进入下一跳。专家中间量不跨跳累积，峰值由最大单跳决定，且复用反向本已需要的权重传输，无额外环遍历。
- **选择性注意力重计算**：以"GPU 容量 − 全重计算下峰值内存"为预算，对每个注意力层各重计算选项按 `c_i,j / m_i,j`（计算节省/内存成本）贪心排序选择，训练开始时计算一次并固定。
- **共享专家处理**：Qwen2-MoE 类架构的共享专家在每个 GPU 上复制，独立于环外计算，不参与调度通信。

## 6. 主要结论与发现

- **单层性能**：相比 all-to-all 平均 2× 加速；E128 在 98K 时达 2.4×；相比 FasterMoE 平均 4.03×（1.41–6.20×），相比 Tutel 平均 2.94×；EP=64 时对二者加速可达 27× 与 16×。
- **显存收益**：单层 MoE 执行峰值显存 EP=8 平均降 3.8×、EP=64 平均降 7.6×（K16 达 13.4×）；相同训练配置下整模峰值降 13.9 GiB；固定 batch 下全模型峰值最多降 35.7%。
- **全模型吞吐与容量**：生产模型吞吐最高提升 2.02×（K16@40K）；最大可训练序列长度从 393K 扩展到 786K（2×），在固定 batch 与全重计算的序列扩展实验中最高扩展 2.85×（90K–150K）；Qwen2-57B 上 RelayMoE 可训练 384K 而 all-to-all OOM。
- **路由模式规律**：专家路由适合 token 计算量大、可摊销权重传输的长序列场景；token 路由在宽专家配置（E384-K12/K16）下优于专家路由（20K 时 3.7×），并在 all-to-all OOM 时仍可运行，二者互补。
- **正确性**：与 all-to-all 的 loss 曲线在 1500 迭代内不可区分。
- **权衡发现**：最大 batch 不一定最快——E64、K12、K16、H512、H768 在 b=12 时吞吐反而更高，说明"省内存换更大 batch"与"省内存换更少重计算"需联合调优。

## 7. 优点

- **问题定位精准**：通过细粒度 profiling 明确指出 MoE 调度缓冲区（而非注意力）是 OOM 边界的主导因素，并用表 1 的架构趋势量化其增长。
- **方法新颖且自洽**：以环替代全量聚合，从结构上消除 top-k 扩展缓冲区；内存上界与 top-k、EP 度解耦，且保持 dropless、无 padding。
- **反向设计巧妙**：重计算与反向梯度计算共用同一次权重传输，无需额外环遍历；"重建→消费→释放"将中间量生命周期压缩到单跳。
- **自适应能力强**：依据完整并行配置（含 SP/CP/ETP）估算通信量选择路由模式，避免绑定单一架构假设。
- **兼容性好**：可与 FlashAttention、CP/SP、MoE Parallel Folding、GroupedGEMM、DeepEP 等现有技术叠加。
- **实验较扎实**：含数学等价性证明 + loss 实证、逐项消融、多维度扩展扫描，并将"执行效率"与"显

存红利"两种效应分离。

## 8. 缺点与局限

- **基线对比的代表性受限**：FasterMoE 与 Tutel 在多数配置下直接 OOM，且作者自己也观察到二者在全部测试中甚至慢于 Megatron-LM 的默认 all-to-all，这使得 4.03×/2.94× 的加速比更像是"对已过时实现的降维打击"，而非与当前最强 MoE 系统的正面比较。
- **缺少与 DeepEP 的跨节点公平对比**：DeepEP 因平台 NVSHMEM/NIC 限制只能在单节点 EP=4 下运行，而 RelayMoE 的主战场恰是跨节点大规模 EP（8–64）。核心卖点（高 EP 度下的显存解耦）缺少与最相关竞品的同条件验证。
- **环状通信的固有代价未被充分讨论**：N 跳环形传递意味着通信跳数与 EP 度线性相关，论文虽用预取/重叠把每跳时间压到 max(计算, 传输)，但未给出 EP 很大（如 128/256）时环延迟、尾延迟（straggler）与负载不均衡的敏感性分析；也未讨论节点内/节点间带宽异构对环拓扑的影响。
- **依赖"计算–通信比"假设**：当单跳计算量很小（如极短序列、极小专家 FFN）时，环可能退化为通信受限，论文的序列长度扫描最低只到 20K/40K，未覆盖极小 batch 或 decode 阶段（推理场景完全未涉及）。
- **重计算策略的调优成本**：选择性注意力重计算采用贪心 `c/m` 排序，属于启发式，未与最优分配（如 DP/ILP）比较，也未报告调优本身的搜索开销；且策略在训练开始时一次性固定，无法适应训练中显存占用的动态变化。
- **评测维度缺口**：未报告训练总时长/GPU 小时、能耗、通信总量的绝对值，也未给出数值精度（BF16/FP8）影响与容错/故障恢复讨论；正确性验证仅 1500 迭代，对长程收敛等价性的证据偏弱。
- **模型覆盖面窄**：三个生产模型全为 Qwen 系（共享专家、SwiGLU），未验证 DeepSeek 系（细粒度专家 + 共享专家 + 多 token 预测）、Mixtral 等其他 MoE 架构，方法在专家极度细粒度（E 数百但单专家极小）时的收益边界不明。
- **实现耦合**：约 2.3K 行代码深度绑定 Megatron-LM 与 MoE Parallel Folding，迁移到其他框架（如 vLLM、SGLang、Megatron 之外的训练栈）的成本与可行性未评估。

## 9. 对领域的意义与启发

- **范式转变**："先聚合再计算"→"边流动边计算"的思路提示，MoE 的显存问题本质是**数据布局与执行顺序**问题，而非单纯的通信优化问题；同样的环式思想可推广到其他需要 top-k 扩展缓冲的算子（如 MoE 推理的 decode 阶段、稀疏注意力）。
- **显存即容量**：论文把显存节省显式转化为三种可用红利（更少重计算、更大 micro-batch、更长序列），并指出"最大 batch 不一定最快"，为大规模训练的超参联合调优提供了实证依据——这对长上下文训练尤为关键（393K→786K 的序列扩展直接对应能力边界）。
- **通信–计算–内存三角的重新权衡**：自适应专家/token 路由把"传权重还是传激活"变成可在线决策的超参，且给出了含 SP/CP/ETP 的解析式，这种"按并行配置估算通信量再选模式"的做法可被其他 EP 系统直接借鉴。
- **反向重计算与通信复用**：让重计算"搭便车"复用反向本就需要的权重传输，是一个可复用的工程范式——任何"反向需要传输某物"的场景都可考虑把中间量重建挂载到该传输上，从而把重计算的额外环遍历成本降为零。
- **对系统栈的启示**：结果说明在 H100 级别硬件上，MoE 训练的 OOM 边界更多由调度缓冲而非模型参数/激活决定，这会影响未来框架的缓冲区管理设计（如按跳流式分配而非预分配全量缓冲）。

## 10. 一句话总结

RelayMoE 用"环式逐跳部分计算 + 就地累加"替代 all-to-all 的全量 top-k 聚合，从结构上把 MoE 峰值显存与 top-k 因子、EP 度解耦，在保持数学等价与 dropless 的前提下，以自适应路由、通信–计算重叠和"搭便车"式重计算换取 2× 级单层加速、最高 2× 吞吐与 2–2.85× 序列长度扩展，是一次针对 MoE 显存瓶颈的、工程完成度较高的系统性重构；其主要短板在于与最强竞品（DeepEP）缺少跨节点同条件对比，以及环拓扑在超大 EP 与通信受限区间的行为尚待验证。
