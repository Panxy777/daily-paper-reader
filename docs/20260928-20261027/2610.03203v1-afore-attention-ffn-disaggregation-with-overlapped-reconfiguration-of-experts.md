## 摘要
由于专家参数量大、专家激活依赖输入以及工作负载动态变化，高效服务混合专家（MoE）模型具有挑战性。专家并行将专家计算分布到多个GPU上，而注意力-FFN解耦（AFD）则将注意力与前馈计算分离为独立的工作池。然而，我们观察到，朴素的AFD实现可能使专家负载不均衡的危害更大：一旦FFN计算成为独立的流水线阶段，过载专家会直接拖慢FFN阶段并降低端到端服务性能。为解决该问题，我们提出AFORE，一种面向基于AFD的MoE服务的及时专家重配置系统。AFORE利用AFD的两个架构特性。第一，AFD在即将到来的微批次到达FFN执行之前暴露其专家-令牌分布，从而能够基于近期未来需求而非过时的历史画像做出放置决策。第二，AFD创造了一个流水线窗口，在该窗口内，目标微批次的专家迁移可以与先前在途微批次的计算重叠。AFORE将专家重配置建模为微批次感知的调度问题，并使用迁移感知调度器决定何时迁移以及迁移哪些专家。AFORE进一步实现轻量级需求预取和基于NVLink的GPU-GPU专家迁移，以降低重配置开销。在四种动态工作负载上对110B参数MoE模型的评估表明，与最强竞争基线相比，AFORE将输出吞吐量提高10.1-17.6%，并将P95令牌间延迟降低7.1-9.5%。与静态放置相比，AFORE平均将吞吐量提高29.8%，平均将P95令牌间延迟降低18.2%。迁移分析进一步表明，AFD流水线重叠可以完全隐藏专家迁移延迟。

## Abstract
Efficient serving of Mixture-of-Experts (MoE) models is challenging due to large expert parameters, input-dependent expert activation, and dynamic workloads. Expert parallelism distributes expert computation across GPUs, while attention-FFN disaggregation (AFD) separates attention and feed-forward computation into independent worker pools. However, we observe that a naive AFD implementation could make expert load imbalance more harmful: once FFN computation becomes an independent pipeline stage, overloaded experts directly slow the FFN stage and degrade end-to-end serving performance. To solve this problem, we present AFORE, a timely expert reconfiguration system for AFD-based MoE serving. AFORE exploits two architectural properties of AFD. First, AFD exposes the expert-token distribution of upcoming microbatches before they reach FFN execution, enabling placement decisions based on near-future demand instead of stale historical profiles. Second, AFD creates a pipeline window in which expert migration for a target microbatch can be overlapped with the computation of preceding in-flight microbatches. AFORE formulates expert reconfiguration as a microbatch-aware scheduling problem and uses a migration-aware scheduler to decide when and which experts to migrate. AFORE further implements lightweight demand prefetching and NVLink-based GPU-GPU expert migration to reduce reconfiguration overhead. Evaluation on a 110B-parameter MoE model across four dynamic workloads shows that AFORE improves output throughput by 10.1-17.6% and reduces P95 inter-token latency by 7.1-9.5% compared with the strongest competing baseline. Compared with static placement, AFORE improves throughput by 29.8% on average and reduces P95 inter-token latency by 18.2% on average. Migration profiling further shows that AFD pipeline overlap can fully hide expert-migration latency.

## 1. 核心问题与整体含义

- **背景**：MoE 模型通过稀疏激活扩大参数规模，但在线服务面临专家参数大、专家激活依赖输入、负载动态变化等挑战。专家并行（EP）将专家分布到多 GPU，注意力-FFN 解耦（AFD）进一步把注意力与 FFN 拆成独立工作池。
- **核心问题**：AFD 虽提升资源利用率和流水线组织能力，却会把专家负载不均衡放大为独立 FFN 阶段的瓶颈。过载专家直接拖慢 FFN 阶段，造成流水线背压，降低端到端吞吐并抬高尾延迟。
- **现有重配置的两难**：
  - **C1 动态且不可预测的需求**：专家需求随请求、层、序列位置和请求混合变化，静态放置或历史统计容易基于过时负载做决策。
  - **C2 不可忽视的系统开销**：放置调度、专家权重迁移、路由元数据更新和 worker 协调若暴露在关键路径上，可能抵消负载均衡收益。
- **关键洞察**：AFD 一方面放大了专家不均衡，另一方面提供了修复它的时间结构：
  - **O1 微批级需求可见**：目标微批次到达 FFN 前，注意力侧已产生专家-令牌分布。
  - **O2 迁移可重叠**：从观察到目标微批需求到其 FFN 执行之间存在流水线窗口，专家迁移可与前序在途微批计算重叠。
- **整体含义**：论文将专家重配置从“静态/历史画像驱动的放置问题”推进为“面向 AFD 流水线的微批感知在线调度问题”，强调不仅要决定“迁哪些专家”，还要决定“何时迁”以及“迁移开销是否值得”。

## 2. 方法论

### 2.1 核心思想

- AFORE 在注意力侧与 FFN 侧之间加入“重叠专家重配置层”，利用目标微批次的近期专家需求做放置决策，并把专家迁移隐藏在 AFD 流水线窗口中。
- 核心原则：**仅当重配置带来的 FFN 时间收益超过其暴露在关键路径上的迁移开销时，才执行迁移**。

### 2.2 问题建模

- FFN 侧有 \(N\) 个专家 worker，托管 \(E\) 个专家；每个微批次 \(m_t\) 的专家需求为 \(d_t=(d_t^1,\dots,d_t^E)\)。
- 放置表示为二值矩阵 \(P=(x_{e,w})\)，\(x_{e,w}=1\) 表示专家 \(e\) 在 worker \(w\) 上有副本；允许一个专家有多个副本以并行服务热点专家。
- 约束包括：每个专家至少一个副本；每个 worker 的专家槽位不超过内存预算 \(K_w\)。
- 工作分配 \(A_t=(a_t^{e,w})\) 决定专家 \(e\) 的多少 token-专家对在 worker \(w\) 上执行。
- 负载建模不仅看 token 数，还考虑 grouped-GEMM 的 M 维 tile：
  - worker 的 tile 负载为 \(T_w(A_t)=\sum_{e:a_t^{e,w}>0}\lceil a_t^{e,w}/M_{\text{tile}}\rceil\)。
  - 不考虑迁移时，目标是最小化最大 worker tile 负载：\(\min \max_w T_w(A_t)\)。
- 迁移成本：从旧放置 \(P_{t-1}\) 切换到新放置 \(P_t\) 时，只计算新增副本的权重传输成本 \(M(\Delta)\)。
- 由于迁移可与前序微批计算重叠，真正暴露在关键路径上的成本为：
  - \(O_t(\Delta)=\max(0, M(\Delta)-W_t)\)，其中 \(W_t\) 是可用重叠窗口。
- 净收益：
  - \(G_t(P_t,A_t)=F(A_t^{\text{base}})-F(A_t)-O_t(\Delta(P_{t-1}\to P_t))\)。
  - 其中 \(F(A_t)=\beta_{\text{tile}}\max_w T_w(A_t)\) 是估计的 FFN 执行时间。
- 调度目标：选择使净收益最大的放置与分配；若最大净收益不大于 0，则保留当前放置。

### 2.3 调度算法

- 采用“固定主副本 + 冗余槽位”的布局，避免每个微批都做全局放置搜索。
- 三阶段贪心搜索：
  1. **分配初始化**：从上一次分配 \(A_{t-1}\) 出发，将专家需求按 tile 数适配到当前微批；无历史时全部放在主副本。
  2. **放置内重平衡**：只在已有副本之间重新分配 tile，不新增权重拷贝；按高负载 worker 到低负载 worker 的顺序贪心迁移，并要求单次迁移 tile 数超过阈值 \(\theta\)。
  3. **放置外重平衡**：探索在空闲冗余槽位上新增专家副本；每个候选副本受全局拷贝预算 \(B\)、槽位安全性和受保护槽位限制；每步用净收益公式评估，保存正收益最高的候选。
- 算法返回微批计划 \(\Pi_t=(P,A_t,\sigma_t,\Delta_t)\)，其中 \(\sigma_t\) 给出专家在 worker 上的物理槽位，\(\Delta_t\) 给出需要新增的权重拷贝。
- 该贪心算法利用已有副本优先、再付费新增副本的顺序，降低搜索空间和迁移频率。

### 2.4 运行时实现

- **需求预取**：注意力 worker 在产生隐藏状态后直接执行 gate/top-k，统计专家 ID 得到局部分布 \(d_{t,a}\)，并通过 StepMesh 写入 FFN 节点的主机内存邮箱；隐藏状态、专家 ID 和路由权重走另一条 AFD 数据路径。
- **共享计划队列**：CPU 调度器汇总所有注意力 worker 的需求，生成计划后发布到共享内存环形队列，所有 FFN worker 映射同一队列读取，避免逐 worker 发送计划消息。
- **重叠迁移**：FFN worker 在目标微批到达前读取计划，并把缺失副本的 GPU-GPU P2P 拷贝提交到专用迁移流；拷贝与当前微批的 FFN 计算重叠。
- **微批边界提交**：新放置在微批边界生效；使用拷贝完成事件检查副本就绪；若拷贝未完成，则在模型流上插入等待。
- **精确分区**：所有 FFN worker 通过 all-gather 获得相同路由元数据，按调度器给出的整数分配 \(a_t^{e,w}\) 和累计边界划分专家 token 序号，使各 worker 执行互不重叠的区间。

## 4. 主要实验结果与发现

- **端到端吞吐与尾延迟**：论文报告 AFORE 在动态回放负载下相较 Static、EPLB 等周期性或静态方案取得更高输出吞吐，并降低 P95 ITL。其优势在请求类型混合、专家需求快速漂移时更明显，说明微批级需求可见性能够缓解“按历史窗口决策导致放置滞后”的问题。
- **与反应式/预测式方案的差异**：HarMoEny、Lina、Libra 分别侧重运行时冗余、热点预测和下一层预取；AFORE 的区别在于把“是否迁移、迁哪些专家、何时迁移”统一到 AFD 流水线窗口与净收益框架下。结果上，AFORE 并非单纯追求最小化最大 worker 负载，而是在负载均衡收益与暴露迁移成本之间取舍，因此在高动态负载下更稳定。
- **迁移成本被有效隐藏**：原始迁移成本可能随新增副本数增加而上升，但由于迁移与在途微批 FFN 计算重叠，暴露成本显著低于原始成本。消融中关闭重叠后，迁移对吞吐和尾延迟的负面影响上升，验证了 AFD 时间结构是该方法成立的关键前提。
- **需求预取的重要性**：w/o Prefetch 使用历史需求替代目标微批真实需求，放置决策会滞后于实际路由分布，导致过载 worker 仍成为 FFN 阶段瓶颈。该消融说明 AFORE 的收益不仅来自重平衡算法，也来自注意力侧提前产生并传递专家-令牌分布。
- **调度开销可控**：共享计划队列、固定主副本与冗余槽位布局、三阶段贪心搜索降低了逐微批全局搜索和逐 worker 协调的成本；论文报告调度器延迟相对于微批执行时间处于可接受范围，未成为新的关键路径瓶颈。
- **负载差距缩小**：以最大 worker tile 负载相对最优的差距衡量，AFORE 能在考虑迁移净收益的前提下缩小热点专家造成的长尾，而不是以频繁迁移换取短暂均衡。

## 5. 贡献与创新点

- **问题重构**：将 AFD 场景下的专家放置从静态/历史画像驱动的周期重平衡，推进为面向微批需求、受流水线窗口约束的在线调度问题。
- **净收益判据**：显式建模迁移的暴露成本，仅当 FFN 执行时间收益超过关键路径上的迁移开销时执行重配置，避免“为均衡而均衡”。
- **AFD 感知的调度算法**：利用“固定主副本 + 冗余槽位”限制搜索空间，通过分配初始化、放置内重平衡、放置外重平衡三阶段贪心，在副本复用与新增拷贝之间形成成本有序的决策流程。
- **运行时机制**：需求预取、共享计划队列、专用迁移流、微批边界提交和精确分区共同把调度决策低开销地落到 EP/FFN worker 上，使迁移与计算重叠具备工程可实现性。
- **系统与实验价值**：在 110B 级 MoE 模型和真实 trace 回放上验证了方法，对比静态、周期重平衡、反应式和预测式基线，较完整地覆盖了吞吐、尾延迟、迁移成本与调度开销等维度。

## 6. 局限与可改进方向

- **对 AFD 流水线结构的依赖**：方法的核心收益来自注意力侧提前可见需求以及迁移可重叠窗口；在非解耦部署、窗口较短或 FFN 阶段本身波动剧烈的系统中，净收益可能下降。
- **贪心算法的局部性**：三阶段贪心降低了搜索成本，但不保证全局最优；当专家需求高度多峰、副本槽位紧张或迁移预算受限时，可能错过更优的跨 worker 重排。
- **成本模型简化**：以 tile 数估计 FFN 时间和以新增副本权重传输估计迁移成本，未完全覆盖网络拥塞、P2P 带宽波动、grouped-GEMM 形状效率差异和副本热缓存效应等二阶因素。
- **多租户与公平性**：实验主要关注吞吐与 P95 ITL，若面向多租户 SLA，需进一步把租户优先级、尾延迟约束和迁移抖动纳入调度目标。
- **扩展性验证**：案例研究为 16 张 A100、FFN 侧 EP 度为 8；更大规模 EP、跨节点迁移和更复杂 PD 配比下的收益与开销仍需验证。

## 7. 总体评价

AFORE 的关键价值不在于提出又一个专家负载均衡启发式，而在于把 AFD 的流水线时间结构转化为重配置机会：注意力侧提前暴露微批专家需求，FFN 侧则利用窗口隐藏迁移。其净收益判据、副本复用优先的贪心搜索和低开销运行时机制相互配合，使“动态专家放置”从理论上的负载优化变成关键路径友好的在线调度。整体上，论文对 AFD 系统中专家不均衡问题的刻画清晰，实验设计覆盖了主要竞争方案与关键消融，结论对大规模 MoE 在线服务具有较强参考价值；后续工作可围绕更精确的成本模型、全局/近似全局搜索以及跨节点扩展性展开。
