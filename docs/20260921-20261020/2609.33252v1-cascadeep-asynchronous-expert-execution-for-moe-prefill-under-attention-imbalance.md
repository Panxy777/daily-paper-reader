## 摘要
混合专家（MoE）服务通常采用数据与专家并行（DEP）：注意力副本运行不同的请求批次，而路由到的专家则分片分布于一个专家并行（EP）组中。在预填充阶段，不同注意力副本完成分发的时间不同，但同步 EP 会延迟专家前馈网络（FFN）计算，直到所有副本的路由输入就绪。请求调度器试图在负载均衡与复用共享提示前缀的键值（KV）缓存以避免冗余预填充计算之间取得平衡。当持有匹配前缀的副本已经过载时，这些目标可能发生冲突，从而留下残余的注意力不均衡。我们提出 ASYNCEP，一种面向 MoE 预填充的分布式执行引擎。ASYNCEP 提出三种机制。异步 EP 允许专家计算在所有注意力副本的 token 就绪之前开始。streamFFN 对已就绪 token 进行批处理，以平衡提前执行与 FFN 计算效率。机会式专家权重获取（OEWF）允许较快的副本获取专家权重并执行其他 GPU 上尚未开始的工作。我们在 DeepSeek-V4-Flash、DeepSeek-V4-Pro 和 GLM-5.3 上评估 ASYNCEP，结果表明 ASYNCEP 在 p95 首 token 时间（TTFT）上最高实现 1.48 倍加速，并将推理吞吐量最高提升 1.17 倍。

## Abstract
Mixture-of-experts (MoE) serving commonly deploys data and expert parallelism (DEP): attention replicas run distinct request batches while routed experts are sharded across an expert-parallel (EP) group. During prefill, attention replicas finish dispatch at different times, but synchronous EP delays expert feed-forward network (FFN) computation until routed inputs from all replicas are ready. Request schedulers seek to balance load while reusing the key-value (KV) cache of shared prompt prefixes to avoid redundant prefill computation. These goals can conflict when a replica holding a matching prefix is already overloaded, leaving residual attention imbalance. We present ASYNCEP, a distributed execution engine for MoE prefill. ASYNCEP proposes three mechanisms. Asynchronous EP allows expert computation to start before tokens from all attention replicas are ready. streamFFN batches ready tokens to balance early execution with FFN computation efficiency. Opportunistic expert weight fetching (OEWF) allows a faster replica to fetch expert weights and execute unstarted work from other GPUs. We evaluate ASYNCEP on DeepSeek-V4-Flash, DeepSeek-V4-Pro, and GLM-5.3, and our results show that ASYNCEP achieves up to 1.48x speedup in p95 time-to-first-token (TTFT) and improves the inference throughput by up to 1.17x.
