## 摘要
混合专家（MoE）层用 E 个专家网络替换 Transformer 的前馈块，并将每个 token 路由到其中 k 个专家。在专家并行（EP）下，专家分布在多个 GPU 上，每个 MoE 层在前向和反向传播中都会执行 all-to-all 集合通信，以将 token 分发到其对应专家，然后再合并结果。在每节点 8 块 AMD Instinct MI300X GPU 的集群上，当 EP32 且采用 top-2 路由时，这些集合通信可占训练步时的 45%；采用 top-6 路由时可占 60%。我们发现，在预训练早期，路由器已经学会以相关模式将 token 分配给专家，这种相关性既存在于层内，也存在于层间。在 top-2 路由下，一层中 0.8% 的专家对会被 42% 的 token 共同选中，而且 token 在某一层选择的专家可以预测其在下一层选择的专家。我们利用这些相关性，将更多 token–专家分配保留在 token 自身所在的 GPU 上，从而减少跨 GPU 和跨节点的通信。相关专家放置将经常被共同选中的专家放在同一 GPU 上。结合一个将每个 token 仅向每个 GPU 发送一次的分发器，最多可消除 58% 的分发行。当序列并行将 token 分片到 EP 组内时，会应用 Token 重排。在注意力之后的 reduce-scatter 过程中，它将每个 token 移动到预测持有其下一层专家的 GPU 上。在单节点上，这将由 token 所在 GPU 服务的 token–专家分配比例从 12.5% 提高到 59%。在 Megatron-LM 中，当 EP 度从 8 到 64、采用 top-2 和 top-6 路由时，这两种方法使 all-to-all 时间缩短为原来的 1/1.16–1/2.63，端到端步时最多缩短为原来的 1/1.41。这两种方法都不会改变模型底层的路由决策或专家参数。

## Abstract
Mixture-of-Experts (MoE) layers replace the feed-forward block of a Transformer with E expert networks, and each token is routed to k of these experts. Under expert parallelism (EP) the experts are distributed across GPUs, and every MoE layer runs all-to-all collectives in the forward and backward passes to dispatch tokens to their experts and then combine the results. On a cluster with 8 AMD Instinct MI300X GPUs per node, these collectives can take 45% of the training step at EP32 with top-2 routing and 60% with top-6 routing. We find that early in pretraining routers have already learned to assign tokens to experts in correlated patterns, both within a layer and across layers. At top-2, 0.8% of the expert pairs in a layer are selected together by 42% of tokens, and the experts a token selects at one layer predict the experts it selects at the next layer. We use these correlations to keep more token--expert assignments on the token's own GPU, which reduces communication across GPUs and across nodes. Correlated expert placement puts experts that are often selected together on the same GPU. Combined with a dispatcher that sends each token to each GPU once, it removes up to 58% of dispatched rows. Token shuffling applies when sequence parallelism shards tokens across the EP group. It moves each token to the GPU predicted to hold its next-layer experts during the reduce-scatter that follows attention. On one node this raises the share of token--expert assignments served on the token's GPU from 12.5% to 59%. In Megatron-LM, across EP degrees from 8 to 64 with top-2 and top-6 routing, the two methods reduce all-to-all time by 1.16-2.63X and end-to-end step time by up to 1.41X. Neither method changes the models' underlying routing decisions or expert parameters.

# 论文结构化总结：Expert Coupling in MoE Pretraining

## 1. 核心问题与整体含义

- **背景**：MoE 层用 E 个专家替换 Transformer 的 FFN，每个 token 路由到 top-k 个专家。在专家并行（EP）下，专家被切分到多个 GPU，每个 MoE 层在前向与反向各需两次 all-to-all（A2A）：dispatch（把 token 送到其专家所在 GPU）与 combine（把专家输出送回）。
- **核心痛点**：A2A 通信量随 EP 度和 top-k 增长；一旦 EP 组跨节点，较慢的节点间链路主导步时。作者在 8×AMD MI300X/节点的集群上实测：A2A 占训练步时的 **13.5%（EP8, top-2）、44.8%（EP32, top-2）、24.0%（EP8, top-6）、60.4%（EP32, top-6）**；在 EP32 + top-6 时，两次集合通信的开销甚至超过专家计算与所有非 MoE 计算之和。
- **既有方法的不足**：
  - 连续放置（expert e 放在 GPU ⌊e/(E/EP)⌋）完全忽略专家共选结构。
  - 专家复制、负载驱动的专家迁移、SmartMoE 等主要**均衡负载、降低峰值链路流量**，但跨 GPU 边界的 token–专家分配比例基本不变，总量不降，且复制要额外显存。
  - DeepSeek-V3 的 node-limited routing 通过**限制路由可选专家**来降低跨节点流量，会改变路由决策。
  - GRACE-MoE / Occult 利用层内专家亲和性，但面向**推理/微调**，使用不等大小分组与专家复制；ExFlow 利用跨层亲和性，但依赖解码时 token 可自由放置，**无法直接迁移到预训练**（预训练中 token 位置由序列分片决定，移动 token 需要额外通信）。
- **论文主张**：预训练早期路由器就已形成稳定的**层内共选**与**跨层可预测**结构，可利用这两类相关性提高 token–专家局部性（token 的专家落在 token 自身 GPU 上的比例），从而在不改变路由决策、不增加专家副本的前提下减少 A2A 通信。

## 2. 方法论

### 2.1 关键经验观察（方法依据）
- **层内相关性**：top-2 模型训练约 2.1B token 后，**0.8% 的专家对（64/8128）承载了 42% 的 token**（独立路由同负载下仅 1.6%）；14 个专家对以 ≥50% 置信度被共选，覆盖 16% 的 token；128 个专家中有 73 个存在"至少 30% 的 token 会同时选中"的固定搭档。该结构在约 1B token 时已出现。
- **跨层相关性**：层 8 的 128 个专家中有 112 个把 ≥30% 的 token 送往层 9 的**某一个特定专家**，中位比例为 48%。即"当前层所选专家可预测下一层专家所在 GPU"。

### 2.2 相关专家放置（Correlated Expert Placement）+ 去重分发器
- **去重分发器（deduplicating dispatcher）**：传统 top-k dispatch 对每个 (token, expert) 分配发一份隐状态副本；改为每个唯一的 **(token, 目的 rank)** 只发一行，行内携带该 rank 上各专家的 ID 与路由概率，接收端展开为 expert-major 顺序；combine 反向同理，按路由概率加权求和后每个 (token, rank) 返回一份部分输出。该技术已有（DeepEP），本文在 Megatron-LM 中实现作为放置的基础。
- **相关放置算法**：
  1. 对每个 MoE 层统计共选矩阵 `W[e,e'] = Σ_t 1[e,e' ∈ S_ℓ(t)]`。
  2. 目标：把 E 个专家均分为 EP 组（每组恰好 E/EP 个，**不改变专家参数显存**），最大化组内 W 之和。
  3. 用 **Kernighan–Lin 风格局部搜索**：从连续放置出发，反复执行增益最大的专家对交换，直到无正增益或达到交换预算 `Imax`。
  4. **多节点分层划分**：先按节点划分（降低跨节点流量），再在每个节点内按 GPU 划分。
  5. 结果是每层的全局专家 ID 的**置换**，不改变路由决策与专家参数，checkpoint 仍按全局专家 ID 加载。

### 2.3 Token 重排（Token Shuffling）
- **适用条件**：仅当 **TP 组 = EP 组**（如 TP8EP8、TP16EP16），不适用于 TP1。此时注意力后的 reduce-scatter 与下一块的 all-gather 本来就要搬运所有 token，**改变"哪个 rank 收到哪个 token"只改索引，不改字节数**，因此可把置换融合进这两个集合通信，**不增加额外集合通信**。
- **归属预测（shuffle planner）**：对每个 token，用其前两层（m−1、m−2）所选专家集合预测第 m 层专家在各 rank 上的分布：
  - 一阶表 `F_m[e, r]`：给定 m−1 层选中 e，其 m 层专家槽落在 rank r 的比例；
  - 二阶表 `S_m[e', e, r]`：再条件于 m−2 层选中 e'；
  - 按支持度回退加权 `w = min(n/(n+β), w_max)`，对前两层 top-k 做双层平均并归一化得到分布 `d_t`；
  - **容量约束下的贪心分配**：每个 rank 必须恰好拥有 T/P 个 token，按置信度间隔 `d(1)−d(2)` 从高到低，把 token 分给尚有余量且概率最大的 rank。
- **融合执行**：shuffled reduce-scatter 把 token（连同残差行）送到预测 owner 并在新 owner 上做残差相加；shuffle-aware all-gather 恢复规范 token 序（注意力依赖顺序）。
- **隐藏开销**：规划器只依赖 ≤ 层 i 的路由、只在层 i+1 的 reduce-scatter 才需要，因此放在**旁路 stream** 上与专家计算和下一段注意力重叠，主 stream 每步仅等待约 1 ms（约 0.02% 步时），另加一个融合 permute+residual kernel（数 ms/步）。
- **表的构建与时效**：离线从记录的路由轨迹拟合；**1,024–4,096 个 token（单个 micro-batch）即可**（4,096 token 时与 524k token 拟合结果的共选矩阵 Pearson 相关 0.93/0.98，指标差距 <1 个百分点）；step 199 拟合已能拿到约一半收益，step 1000 接近最终值（差 2–3 个百分点），step 1400 后几乎等同；长训练建议约每 1000 步重拟合一次。
