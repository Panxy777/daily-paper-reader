## 摘要
细粒度混合专家（MoE）是扩展大语言模型的事实标准架构。然而，动态专家负载不均衡会导致严重的内存波动，从而降低训练效率。现有系统依赖静态内存供给：要么过度供给，在正常执行期间使 GPU 内存闲置；要么供给不足，在负载峰值出现时引发内存溢出崩溃和昂贵的人工回滚。为解决这些挑战，我们提出 BaGuaLu-2，一个通过灵活供给消除这一困境的大规模 MoE 训练系统。通过将内存分配从静态的一次性调优选择转变为持续且细粒度的控制，BaGuaLu-2 按需为每个训练批次精确分配激活内存。此外，它通过系统优化抵消任何动态管理开销。BaGuaLu-2 展现出卓越的可扩展性，在 12,288 块 GPU 上训练具有 1.04 万亿参数的模型，同时在 35% MFU 下持续超过 2 EFlops。与最先进系统相比，BaGuaLu-2 相比 Megatron-Kuai 和 AdaPipe 分别带来 1.14 倍和 1.13 倍的平均吞吐量提升。

## Abstract
Fine-grained Mixture-of-Experts (MoE) is the de facto architecture for scaling large language models. However, dynamic expert load imbalance causes severe memory fluctuations that degrade training efficiency. Existing systems rely on static memory provisioning: they either over-provision, leaving GPU memory idle during normal execution, or under- provision, inviting out-of-memory crashes and costly manual rollbacks when load spikes occur. To address these challenges, we propose BaGuaLu-2, a large-scale MoE training system that eliminates this dilemma through flexible provisioning. By transforming memory allocation from a static, one-time tuning choice into a continuous and fine-grained control. BaGuaLu-2 grants exact activation memory on demand for each training batch. Furthermore, it offsets any dynamic management overhead through system optimizations. BaGuaLu-2 demonstrates exceptional scalability, training a model with 1040 billion parameters across 12,288 GPUs while sustaining over 2 EFlops at 35% MFU. Compared with state-of-the-art systems, BaGuaLu-2 delivers 1.14x and 1.13x average throughput improvements over Megatron-Kuai and AdaPipe, respectively.

## 一、核心问题与研究动机

- **背景**：细粒度 MoE（如 DeepSeek-V3 的 8/256、Kimi-K2 的 8/384）已成为扩展 LLM 的主流架构，它在不按比例增加每 token 计算量的前提下提升模型容量，但也放大了 MoE 相关的激活内存开销。
- **核心问题**：MoE 的动态稀疏路由天然带来专家负载不均衡，进而导致**激活显存随迭代剧烈波动**。作者在万卡级集群上实测：约 97.1% 的迭代失衡率低于 1.2×，但约 2.9% 的迭代超过该值，最高达 2.6× 尖峰。
- **现有系统的两难**：
  - **过配（over-provision）**：为最坏情况预留显存，正常迭代中大量显存闲置，MFU 长期偏低（实测仅 24.6%）。
  - **欠配（under-provision）**：按平均情况配置以追求高 MFU（30.0%），但遇到尖峰即 OOM，需人工干预与冷重启；实测单次恢复开销 284 秒，约为正常迭代的 16 倍，且不含人工响应延迟。
- **根因定位**：权重与优化器状态可通过模型并行/ZeRO 切分且跨迭代稳定；**激活内存无法有效切分**（集群越大所需输入数据越多以维持计算密度），且随负载不可预测地波动，因此激活内存是效率与稳定性矛盾的关键。
- **理论论证**：作者用四步链条论证尖峰是细粒度 MoE 的**架构固有性质而非算法缺陷**——(1) top-k 路由的采样随机性；(2) 数据分布偏斜（长程均衡机制只能依据过去迭代的聚合负载，滞后至少一个迭代）；(3) 高专家并行度下专家级失衡直接转为设备级 token 集中；(4) warmup 阶段多个前向批次堆叠、无反向释放。并用 DeepSeek-V3.1-Terminus 与 GLM-4.7 在五个 SWE 任务域上的实测，证明负载偏斜随输入数据系统性变化。
- **整体含义**：现有系统"静态供给 + 静态缓解"的工作流隐含"激活内存跨迭代稳定"的假设，该假设在细粒度 MoE 下已不成立，需要把内存供给变为**运行时连续控制**。

## 二、方法论

### 2.1 核心思想

- 提出 **flexible activation provisioning（灵活激活供给）**：将激活内存分配从"训练前一次性调优的粗粒度静态策略"转变为"每个微批次、每个算子的连续细粒度控制"。
- 双区间策略：(i) 失衡温和时采用"稳态缓解"以启用高吞吐并行配置、吃满显存；(ii) 失衡严重时动态加码缓解以避免 OOM，从而规避冷重启这一更大代价。
- 系统在**每个流水线调度点**为下一个微批次决策执行计划（内存用量 + 算子执行顺序），由三个组件串接完成。

### 2.2 关键技术

**① 激活内存代价模型（§IV）**

- 每个算子刻画为元组 `(Δt, Δm)`：执行时间与激活内存增量（前向为正、反向为负）；在"时间–显存"平面上，前向算子为右上上升的直角三角形，反向为右下下降的三角形。由于每个算子对应单次 kernel launch，分段线性近似能较好贴合真实显存曲线。
- 层级聚合：算子 → 微批次（三角形拼接，总高 ΣΔm、总宽 ΣΔt）→ 迭代（warmup 单调上升、1F1B 稳态在平台附近振荡、cooldown 单调下降），由此得出**峰值形成机理**：峰值主要在前向堆叠的 warmup 阶段形成，进入 cooldown 后不可能 OOM。
- 缓解策略建模：重计算、卸载、量化均可视为对代价元组的变换（降 Δm、增 Δt）。采用 **roofline 式"缓解带宽"模型**（GB 节省 / 秒开销 vs. 激活大小）：小于拐点 S_i 时受 launch 开销限制，大于则饱和于峰值带宽 B_i；两个策略按拐点与交叉点 P1 = S_i·B_j/B_i 比较。经验规律：计算密集型算子倾向卸载，访存密集型（如 LayerNorm）倾向重计算。

**② 自适应激活供给（§V-A）**

- **优化目标**：`min ΣΔt  s.t. peak memory ≤ M_max`，且因 MoE 算子代价只有运行时（gate 计算后）才可知，必须**在线求解**。
- **延迟规划（deferred planning）**：MoE gate 执行前无法预知实际负载，无法为当前批次预留精确配额；但由迭代级模型可知峰值由多批次累积，故可推迟到下一批次调整——warmup 阶段尚有时间压低后续批次配额；稳态阶段可在 gate 已算、专家未算时降级为 MoE 模块全重计算。
- **算法 1（流水线感知内存预算分配）**：warmup 阶段把剩余容量在未启动批次间均分并为每批保留最小预算 M0 以保证可行性；稳态阶段把反向释放的显存全部分给新批次；两阶段都用**实际消耗**回写预算，避免高估级联为后续欠分配。
- **算法 2（roofline 引导的迭代贪心缓解）**：每轮评估所有单算子候选策略的内存收益，选收益最大者，检查冲突后应用，直至满足预算；每轮重估收益（策略间会改变彼此价值）。
- **异构缓解冲突检测**：识别两类冲突——*多精度冲突*（同一张量被不同消费者量化为不同精度，如 router 需 FP32、shared expert 用 BF16/FP8，导致多副本共存反而增存）与*多设备冲突*（同一张量在一处卸载、在另一处仍驻留 GPU，卸载无收益）。检测方式为回溯每个被优化算子到源激活张量，校验所有消费者的精度与设备放置一致；冲突候选直接拒绝（因其收益必然小于已应用的策略）。

**③ 融合双批次执行（§V-B）**

- 动机：缓解策略引入的额外算子落在关键路径上，成为纯性能惩罚；而稳态下 GPU 同时持有四类算子——当前前向 F、当前反向 B、上一前向批次的卸载 O、下一反向批次的恢复 R，**类内为链式依赖、类间无数据依赖**，存在重排重叠空间。
- **DP 形式化**：状态 `F[i][j][k][l]` 表示前 i 个 F、j 个 B、k 个 O、l 个 R 算子的最小执行时间，转移为 `F[i][j][k][l] = min{ F[w][x][y][z] + T(w:i, x:j, y:k, z:l) }`，记录最优转移点以重构顺序；状态数 O(|F||B||O||R|)，朴素复杂度 O(|F|²|B|²|O|²|R|²)。
- **运行时加速**：(a) 按通信算子切分阶段，把同一阶段内连续计算算子压缩为单个 DP 状态（一个 MoE 前向批次 20+ 算子仅 4 个阶段）；(b) 以离散化预算值为 key 缓存 DP 结果，利用流水线相位每 B_w 批重复、失衡率多数迭代稳定的时间局部性，使摊销开销趋近于零。
- **正确性论证**：DP 仅扩展各类前缀、不重排类内顺序，故保留全部类内生产者–消费者依赖；类间由调度点间的同步屏障保证 O 消费的 (x−1) 批激活与 R 产出的 (y+1) 批激活均已/将就绪；要求流水线并行度 > 2（x−y>2），评测中 PP 均 ≥ 4，故边界情形不出现。
