Abstract 

This paper presents Memory- and Communication-Aware Framework for Long-Context LLM Inference (MCF) that optimizes long-context inference through communication-aware and stage-adaptive KV-cache layout transitions. At the core of MCF is Memory-Aware Replication and Scheduling (MARS), a dynamic orchestration mechanism for chunked prefill. MARS exploits early-stage memory headroom by se-lectively replicating highly reused KV blocks, improving locality and hiding KV propagation latency behind atten-tion computation. As prefill progresses and memory pres-sure increases, MARS progressively drains redundant repli-cas and converges the KV cache into a sharded decode-ready layout, avoiding expensive layout conversion at the prefill–decode boundary. For decoding, MCF adopts a query-centric execution model in which KV shards remain station-ary while lightweight query tensors are routed across work-ers. This changes communication from KV-cache-dependent transfer to query-dependent transfer, reducing communi-cation growth with context length. MCF further integrates a hardware-software co-designed execution layer based on an FPGA compute-NIC datapath, enabling metadata-driven KV routing and collective operations directly in the network path. Experiments show that MCF improves TTFT, through-put, and scalability over state-of-the-art distributed inference systems, with larger benefits as context length and cluster size increase. 

Keywords: LLM Serving, Distributed Inference, KV-Cache Management, In-Network Computing, Zero-copy Communi-cation 

1 Introduction 

Long-context inference is becoming a critical workload for Large Language Models (LLMs). Applications such as re-trieval augmented generation [9], code generation [14], doc-ument analysis [17], and agentic reasoning often require prompts with tens of thousands of tokens. For such work-loads, the prefill stage becomes a dominant contributor to Time-To-First-Token (TTFT), because the system must pro-cess the entire input context and materialize the correspond-ing Key-Value (KV) cache before decoding can begin. Many existing distributed inference systems rely on ten-sor parallelism and pipeline parallelism. Tensor parallelism partitions model weights across devices, while pipeline par-allelism partitions model layers. These techniques are effec-tive for scaling model parameters and computation, but they do not directly address the sequence-dependent KV-cache growth in long-context inference. During prefill, each new query chunk must attend to all historical KV blocks. During decode, every generated token must access the increased KV cache. As a result, long-context inference introduces dif-ferent types of memory and communication bottleneck to conventional model-parallel weight partitioning. Context parallelism addresses this issue by partitioning the sequence dimension and distributing KV cache across workers. However, existing context-parallel designs [12, 13] often rely on static KV sharding and fixed communication patterns, such as ring-style KV propagation. While such de-signs preserve a memory-efficient layout, they repeatedly move historical KV blocks during inference. As the num-ber of chunks grows, this repeated communication becomes increasingly expensive under bandwidth-constrained dis-tributed inference. It would also be inefficient in heteroge-neous or dynamically changing communication environ-ments, where link bandwidth, latency, or node availability can vary over time. Moreover, we observe that prefill is not a uniform exe-cution phase. Early in prefill, the accumulated KV cache is small and each worker has substantial memory headroom. At the same time, early KV blocks have the highest future reuse because they will be attended by many subsequent chunks. Near the end of prefill, memory pressure increases and the system must recover a compact KV layout suitable

We thus propose MCF, a Memory-Communication-Aware Distributed Inference Framework for Long-Context LLMs to response to this challenge. At the core of MCF is MARS, a stage-aware KV-cache orchestrator that dynamically con-trols KV replication and convergence during chunked prefill. MARS temporarily replicates high-reuse KV blocks when memory headroom is available, reduces the frequency of re-mote KV accesses and the critical-path latency of KV trans-fers in later chunks, and progressively retires redundant replicas as their reuse window expires. By the end of pre-fill, MARS guarantees that all KV blocks converge to an owner-only sharded layout, enabling efficient KV-stationary decode. MCF further introduces a distributed chunked-prefill ex-ecution model that pipelines local computation with KV propagation and missing-block fetching. Rather than treat-ing communication as a serialized phase after computation, MCF overlaps chunk execution with dynamic KV movement. This improves TTFT for long-context inference. To realize this dynamic execution efficiently, we design a hardware-software co-designed unified execution frame-work. The software runtime emits MARS metadata, includ-ing routing identifiers, operation codes, KV block identifiers, and destination sets. The hardware maps this metadata to an FPGA compute-NIC datapath that performs KV propagation, collective communication, and decode-state reduction in the data plane. This design translates MARS’s dynamic schedul-ing decisions into high-performance distributed inference. This paper makes three key contributions: 

• We propose MARS , a stage-aware KV-cache orchestra-tor that dynamically replicates, drains, and converges KV blocks across prefill stages, exploiting early mem-ory headroom while guaranteeing a sharded decode-ready layout. 

• We design a distributed chunked-prefill execu-tion model that pipelines local computation with KV propagation and remote KV-cache fetching, improving compute-communication overlap and reducing TTFT for long-context inference. 

• We design a hardware-software co-designed uni-fied execution framework that bridges MARS and hardware execution. By integrating a metadata-driven FPGA compute-NIC datapath, the framework realizes dynamic KV routing and collective operations in hard-ware, enabling high-performance distributed infer-ence. 

2 Background and Motivation 

In this section, we first discuss distributed LLM inference from the perspective of KV-cache memory requirements. We then briefly review tensor parallelism, pipeline parallelism, sequence parallelism, and context parallelism. Finally, we identify the key bottlenecks in existing long-context LLM inference systems, particularly those arising from static KV-cache layouts, and use these limitations to motivate our work. 

2.1 Distributed LLM Inference 

Large language model inference is commonly divided into two stages: prefill and decode. Given an input prompt of length 𝑆 , the prefill stage processes all prompt tokens and materializes KV cache for every transformer layer. The de-code stage then generates output tokens autoregressively, where each new query attends to the accumulated KV cache. As context length increases, the KV cache becomes a major memory and communication bottleneck. For a model with 

𝐿 transformer layers, 𝐻 𝑘𝑣 KV heads, head dimension 𝑑 , and element size 𝑏 , the KV-cache memory per token is 

𝑀 token = 2𝐿𝐻 𝑘𝑣 𝑑𝑏 (1) where the factor of two corresponds to keys and values. Therefore, the KV-cache footprint grows linearly with se-quence length. Long-context inference further amplifies this issue because each prefill chunk must attend to all histori-cal KV blocks, while every decode step must access the full accumulated KV cache. This makes long-context inference fundamentally different from short-context inference: the system is no longer dominated only by model weights and matrix multiplication, but also by the placement, movement, and reuse of KV-cache states. 

2.2 Tensor Parallelism 

Tensor parallelism (TP) is a widely used method for scaling large transformer models across multiple accelerators. TP partitions large matrix operations within each transformer layer across devices. For example, linear projections in at-tention and feed-forward networks can be split along col-umn or row dimensions, and devices exchange partial results through collective communication such as all-reduce or all-gather. This approach is effective for distributing model pa-rameters and compute within a layer, and has been adopted in systems such as Megatron-LM [24]. 

2.3 Pipeline Parallelism 

Pipeline parallelism (PP) partitions a transformer model along the layer dimension. Each device stores and executes a subset of layers, and microbatches are pipelined across stages. PP is effective for distributing model weights across devices and increasing throughput for batched workloads. It has been combined with tensor and data parallelism in large-scale systems such as Megatron-LM [19]. 

2.4 Sequence Parallelism 

Sequence parallelism (SP) partitions tensors along the se-quence dimension. Instead of replicating the entire sequence

More recent long-context systems further explore SP as a way to scale sequence length beyond the memory capacity of a single accelerator. 

2.5 Context Parallelism 

Context parallelism (CP) can be viewed as a sequence-parallel strategy specialized for long-context attention and KV-cache management. In CP, the input context and KV cache are partitioned across devices. Each worker owns a subset of the sequence and participates in distributed attention computation. This layout is attractive because it reduces per-device KV-cache memory from 𝑂 (𝑆 ) to approxi-mately 𝑂 (𝑆 /𝑁 ) for 𝑁 workers. Existing context parallelism methods mainly differ in how they communicate attention states across devices. Two representative approaches are Ring Attention[13] and DeepSpeed-Ulysses[6]. 

Ring Attention. Ring Attention partitions the sequence into blocks and arranges workers in a logical ring. During at-tention computation, each worker computes partial attention using local KV blocks while KV blocks are circulated around the ring. This blockwise design enables overlap between KV communication and attention computation, and allows long sequences to be processed across multiple devices [13]. Ring Attention is memory efficient because each KV block can remain owned by one worker. However, during chunked pre-fill, historical KV blocks may be repeatedly streamed across workers for later chunks. As the length of input sequence increases, the total KV movement can grow rapidly. If the prompt is divided into 𝐶 chunks and each chunk at-tends to all previous chunks, a ring-style design may commu-nicate prefix KV blocks repeatedly. DeepSpeed-Ulysses. DeepSpeed-Ulysses is another long-sequence parallelism approach that partitions the sequence dimension and uses collective communication to redistribute tensors for attention computation [6]. However, Ulysses-style all-to-all communication still re-lies on relatively structured collective operations. For long-context inference, especially chunked prefill followed by decode, the optimal communication pattern can change over time. Early in prefill, memory pressure is low and historical KV blocks have high future reuse. Later in prefill, mem-ory pressure increases and the system must converge to a compact sharded KV layout for decode. A fixed commu-nication/layout strategy cannot fully exploit this temporal structure. 

2.6 Limitations of Static KV Layouts 

The above approaches demonstrate that distributing the se-quence dimension is necessary for long-context inference. However, most existing designs rely on relatively static ex-ecution layouts. Ring Attention keeps an owner-only KV layout and repeatedly propagates KV blocks. Ulysses-style systems rely on structured all-to-all layout transformations. These approaches are effective for regular distributed atten-tion computation, but they do not explicitly optimize the temporal reuse pattern of chunked prefill. The key observation behind MCF is that prefill is not a uni-form phase. At the beginning of prefill, only a small number of KV blocks have been generated, so each worker has mem-ory headroom. At the same time, early KV blocks have the highest future reuse because they will be attended by many subsequent chunks. Near the end of prefill, memory pres-sure becomes high, and the system must recover a balanced sharded KV layout for decode. This temporal asymmetry suggests that neither pure sharding nor full replication is optimal. Pure sharding minimizes memory usage but can repeatedly fetch or stream historical KV blocks. Full replication reduces remote KV access but is not memory scalable and leaves an inefficient layout for decode. The desired design should temporarily use available memory to replicate high-reuse KV blocks during early prefill, then progressively retire redundant replicas and converge to a sharded layout before decode. 

2.7 Motivation for MCF 

MCF is motivated by the need for a dynamic, stage-aware ex-ecution layout for long-context inference. Instead of treating KV placement as a fixed policy, MCF treats it as a runtime scheduling problem. Its core mechanism, MARS, divides pre-fill into multiple stages and dynamically orchestrates KV-cache replication, draining, and convergence according to memory headroom and expected future reuse. During early prefill, MARS(Section 4) creates temporary replicas for high-reuse KV blocks to reduce repeated remote KV access. During middle prefill, MARS adjusts replica fac-tors as memory pressure increases. By the end of prefill,

The FPGA compute-NIC datapath then uses this metadata to perform KV dissemination, collective communication and decode-state reduction.

Its central design principle is that the preferred KV layout is stage-dependent. During chunked prefill, early KV blocks are reused by many later chunks, while late KV blocks have limited remaining reuse. MCF therefore allows temporary replication of high-reuse KV blocks when memory headroom is available. 3.1 Progressive KV Layout 

MCF processes the input prompt in chunks. For each gen-erated KV block, MARS assigns a permanent owner node according to the final sharding policy. The owner copy is never removed. In addition, MARS may create temporary replicas during prefill to reduce later remote KV accesses. These replicas are most beneficial for early KV blocks be-cause they have the largest future reuse window. As prefill progresses, accumulated KV-cache memory in-creases and the benefit of replicating newly generated blocks decreases. MARS therefore gradually reduces replica factors and marks redundant replicas for draining. Draining replicas may still serve in-flight computation, but they are excluded from future scheduling decisions and are removed once no longer needed. This process avoids bulk layout conversion: because the owner copy always remains valid, convergence only requires retiring temporary replicas rather than migrat-ing KV data. At the end of prefill, all temporary replicas are removed and each KV block remains only on its owner node. This owner-only layout is decode-ready. During decode, MCF keeps KV shards stationary and routes only the current query or compact partial attention states across nodes. Each node computes attention over its local KV shard, and the partial results are reduced to form the global attention output. 

3.2 Compute-NIC Execution Substrate 

To execute this progressive layout efficiently, each MCF node integrates a local compute engine, a KV memory pool, and a metadata-driven FPGA compute-NIC datapath. The com-pute engine performs local transformer computation and emits either KV blocks during prefill or compact partial at-tention states during decode. The KV memory pool stores both permanent owner blocks and temporary replicas. The MARS runtime attaches compact metadata to each tensor payload, including the execution stage, operation type, KV-block identifier, route identifier, destination set, and re-duction operator. The FPGA NIC datapath interprets this metadata to perform the corresponding communication ac-tion, such as KV propagation during prefill or partial-state reduction during decode. By moving routing and collective operations into the datapath, MCF avoids host-side commu-nication control on the critical path and enables computation and communication to proceed in a pipelined manner. Overall, MCF uses different communication policies for different inference stages: prefill uses memory-aware tempo-rary KV replication to reduce exposed remote access latency, while decode uses a KV-stationary sharded layout to avoid moving accumulated KV cache. This progressive transition is the basis for the MARS scheduling algorithm described in the following section.

To enforce this convergence safely, MARS incorporates Progressive Replica Convergence as its runtime mechanism. Each temporary KV replica is associated with a lifecycle state. A valid replica can serve local attention computation. When the replica factor decreases, redundant replicas are marked as draining rather than immediately invalidated. A draining replica remains readable by in-flight chunks but is excluded from future scheduling decisions. Once all dependent chunks complete, the replica is invalidated and its buffer space is returned to the memory manager. This metadata-driven con-vergence avoids bulk KV migration because the owner shard is never removed. As a result, replica shrinking primarily involves directory updates and buffer-state transitions rather than additional data movement. After convergence, MARS exposes a decode-ready lay-out: each KV block has a unique owner and the accumu-lated KV cache is evenly sharded across workers. Decode therefore uses a KV-stationary execution model. Each node attends over its local KV shard and emits compact online-softmax states, such as the local maximum, normalization sum, and partial output, which are reduced across nodes to obtain the global attention result. Thus, MARS bridges the layout mismatch between communication-optimized prefill and memory-scalable decode without requiring an explicit KV redistribution phase. 

5 Unified Progressive Execution Layout 

MARS produces a progressive KV-cache layout that changes across execution stages. To execute this dynamic layout ef-ficiently, MCF introduces a Unified Progressive Execution Layout that maps MARS scheduling decisions into a FPGA-based cluster. The central design principle is to avoid treating compu-tation and communication as separate runtime phases. In-stead, each FPGA node integrates a local compute engine with a SmartNIC. The compute engine produces either KV-cache blocks during prefill or compact partial attention states during decode. These outputs are packetized with MARS-generated metadata and sent directly to the NIC datapath through an AXI-Stream interface. The NIC then decodes the metadata and performs the required communication opera-tion, such as multicast, all-to-all exchange, or all-reduce. In this way, MARS decisions are enforced directly in the data plane, bypassing host-side control flow latency and enabling full pipelining. This buffer contains a payload FIFO and a metadata FIFO. The payload FIFO stores activa-tion tensors, including prefill KV blocks and decode partial states. The packetizer combines the payload and metadata into an AXI-Stream packet. This design allows the compute pipeline to continue producing data even when the NIC experiences temporary congestion, as long as the packetization buffer has sufficient capacity. The stage field distinguishes prefill and decode. The op 

field specifies whether the packet carries a KV replica, a replica invalidation request, a query or state packet, or a re-duction message. The src , dst , and route_id fields identify the routing action selected by MARS. The collective field indicates whether the packet participates in point-to-point forwarding, multicast dissemination, all-to-all exchange, or all-reduce. The reduce_op field specifies the operation re-quired during decode, such as maximum comparison, sum-mation, or online-softmax state merge. The NIC datapath is metadata-driven. When an AXI-Stream packet arrives from the packetization buffer, the packet parser separates metadata from payload. The metadata decoder then dispatches the packet to the appro-priate hardware engine. KV replication packets are sent to the forwarding or multicast engine, which follows the mesh-aware route generated by MARS. Collective packets are handled by the all-to-all engine. Decode partial-state packets are sent to the reduction engine, which performs the maximum and summation operations required to merge distributed softmax statistics. Since the NIC performs these operations directly in hardware, the host CPU is removed from the critical path of KV routing and decode-state reduction. This unified packetized interface supports both stages of inference. During prefill, the payload is dominated by KV-cache data. MARS may assign a high replica factor to early high-reuse KV blocks, and the corresponding metadata instructs the NIC to multicast these KV blocks through a mesh-aware dissemination path. When memory pressure increases, MARS reduces the replica factor and generates metadata that marks redundant replicas as draining or in-valid. Since the owner shard is never removed, replica con-vergence only requires directory updates and buffer-state transitions, avoiding bulk KV migration. During decode, the same datapath switches to a KV station-ary execution mode. The accumulated KV cache is already evenly sharded across nodes by MARS, so the system avoids moving or replicating bulk KV data. Instead, each node com-putes attention over its local KV shard and exchanges only lightweight query or partial-state packets. The reduction engine merges local softmax states using online-softmax-compatible operations. This behavior is similar to distributed Flash-Decoding-style execution: the long KV dimension is partitioned across workers, local attention is computed inde-pendently, and compact partial states are reduced to obtain the final attention output. The benefit of this design is that prefill and decode share the same hardware communication substrate while using different metadata policies. Prefill uses KV-centric dissemina-tion to exploit early memory headroom and reduce repeated remote KV access. Decode uses query/state-centric routing over a stationary, balanced KV layout. The transition be-tween the two does not require a separate data redistribution phase because MARS guarantees that all temporary replicas have converged to owner shards by the end of prefill. Overall, Unified Progressive Execution Layout turns MARS from an analytical scheduling algorithm into an executable hardware protocol. MARS determines the layout, route, and operation type; the compute core produces the corresponding payload; the packetization buffer attaches metadata; and the NIC datapath executes the required communication or reduction operation. By fusing local computation with metadata-driven communication, MCF supports communication-efficient chunked prefill and distributed Flash-Decoding-style decode within a single FPGA execution framework.

7 Related Work 

We discuss related work for context parallelism algorithm and dynamic memory management for LLM inference, and then draw the difference between state of the art approach and MCF. 

7.1 Context Parallelism Algorithms 

Context parallelism partitions maximum sequence dimen-sion across devices. For example, Li et al. [12] proposed Ring Self-Attention (RSA) in which each device stores only a subsequence, rather than the full sequence. RSA circulated key embeddings across devices to compute attention scores. After that, it circulates value embeddings to compute the attention outputs. This way, RSA improved scalability for long-sequence training to some extent. However, RSA still re-quired the distributed attention-score blocks to be explicitly stored in memory. To avoid storing explicitly attention-score blocks in mem-ory, Liu et al. [13] proposed Ring Attention, which imple-mented ring-based sequence parallelism by combining KV-block circulation with blockwise Transformer computation. In Ring Attention, the input sequence is partitioned across devices, so that each device keeps a local Q, K, and V block initially. Then, KV blocks circulate based on a ring structure while each query block fixed to an associated device. As each KV block arrives, the device performs partial at-tention on these KVcache and update the attention score in a flashattention manner [3]. This reduces the peak activa-tion memory per device to depend primarily on the local block size rather than the full sequence length. However, existing ring-based methods still impose a static communi-cation structure. RSA and Ring Attention assume that KV blocks traverse a predetermined ring. This is efficient when devices are homogeneous and communication can be fully 

11 EuroSys ’27, April 2027, Rabat, Morocco Zhang et al. 

overlapped with blockwise computation. In practice, long-context inference can be more dynamic: memory pressure changes across prefill and decoding; different context blocks have different reuse patterns; and bandwidth, latency, or device availability can vary across the system. A fixed ring traversal can therefore become inefficient when some links are slower or when certain KV blocks would benefit from temporary replication rather than repeated circulation. ZigZag Attention[16] addresses this bottleneck by reorder-ing the sequence blocks to balance the workload. Instead of a linear traversal, it employs a "zigzag" scheduling strat-egy that pairs computation-heavy blocks (near the end of the sequence) with computation-light blocks (near the be-ginning) within the same communication step. By ensuring that the workload is approximately equal across all devices in the ring, ZigZag Attention achieves nearly 2 × higher computational efficiency compared to unoptimized causal Ring Attention, all while maintaining the same communi-cation overhead and memory benefits. While ZigZag op-timizes the load balance within a static ring, it does not address the fundamental resource tension between the two distinct phases of long-context inference. The Prefill phase is highly compute-bound, requiring massive throughput to process the prompt, whereas the Decoding phase is strictly memory-bandwidth bound (IO-bound) and sensitive to per-token latency. Attempting to manage both within a single, fixed ring often leads to "prefill-stalls," where long context processing blocks the generation of shorter requests. Prefill-Decoding Disaggregation[29] resolves this by decoupling the two phases into distinct hardware pools: prefill nodes use TP/PP/CP for high-throughput ingestion on premium GPUs, while decoding nodes specialize in autoregressive genera-tion. KV cache is handed off between pools over high-speed interconnects. This separation enables independent scaling and optimizes TCO. The proposed MCF addresses this limitation by treating context parallelism not merely as a static sequence-partitioning method, but as a dynamic memory-communication scheduling problem. Instead of forcing every KV block to follow the same fixed traversal pattern, MCF dynamically decides whether a context block should be sharded, replicated, migrated, or circulated according to the current inference stage, memory pressure, expected reuse, and communication cost. In this sense, MCF generalises ring-based context parallelism: it preserves the benefit of distributing long-context attention across devices, but removes the assumption that one fixed ring schedule is always optimal. 

7.2 Dynamic Memory Management for LLM Inference 

Efficient LLM serving requires careful management of model weights, intermediate activations, attention buffers, and the KV cache. For long-context inference, the KV cache is par-ticularly important because it grows with the number of processed tokens and must be repeatedly accessed during decoding. Kwon et al. [8] proposed PagedAttention, which treats KV-cache storage using a paging-inspired mechanism, reducing memory fragmentation and enabling flexible KV-cache sharing across requests. Sheng et al. [23] proposed FlexGen for high-throughput generation by coordinating GPU, CPU, and disk memory. Such related work discusses that LLM inference performance is strongly constrained by memory placement and scheduling. Agrawal et al. [1] introduces chunked prefill and stall-free scheduling. DistServe and Splitwise separate prefill and decoding across different GPU resources [20, 29]. Other work focuses directly on KV-cache movement and reuse. Liu et al. [15] compressed and streamed KV caches to reduce context-loading delay when reusing long contexts across requests. Qin et al. [22] proposed a KV-cache-centric serving architecture by separating prefill and decoding clus-ters and using CPU, DRAM, SSD, and NIC resources to build a distributed KV-cache pool. These systems recognised that KV-cache movement could be a main bottleneck in LLM serving. Unlike these systems, which focus on KV reuse and memory hierarchy, MCF introduces stage-aware KV place-ment inside CP itself: MARS temporarily replicates high-reuse blocks during low-pressure prefill stages and falls back to sharding as memory tightens MCF exploits these stage-dependent changes through MARS: high-reuse blocks can be temporarily replicated when memory pressure is low, while the system can fall back to sharding when memory becomes scarce. Thus, MCF introduces a dynamic memory-management layer inside CP, rather than treating KV-cache layout as fixed once the sequence has been partitioned. 

8 Conclusion 

We propose MARS, a stage-aware KV-cache orchestrator, that dynamically replicates, removes, and converges KV blocks across prefill stages. MARS improves access locality for highly reused historical KV blocks while ensuring that temporary replication remains memory-bounded and that the final layout is compatible with efficient sharded decoding. We further introduced a distributed chunked-prefill execu-tion model that pipelines local attention computation with KV propagation and remote KV-cache fetching, allowing communication latency to be hidden behind useful compu-tation whenever feasible. For example, prior work did not explicitly identify the runtime conditions under which com-munication overhead could be hidden, as formulated in Equa-tion (8). We also propose a hardware-software co-designed execution framework that connects MARS-level scheduling decisions to the underlying distributed execution substrate.
