## 摘要
在专家并行混合专家（MoE）服务中，dispatch 将 token 移动到承载其所选专家的加速器，combine 将专家输出返回给每个 token 的所有者。这两个操作均位于关键路径上，在多节点部署中可能主导 MoE 层延迟。我们提出 INC-MoE，一种专家并行 MoE 层，将 dispatch 和 combine 卸载到网络交换机，并使这两个集合通信彼此重叠并与专家计算重叠。Dispatch 通过交换机侧多播使用网内 AllGather，combine 通过交换机侧归约使用网内 ReduceScatter。两个集合通信在端主机与交换机之间使用消息语义。由于网内集合通信加载每条链路的相反方向，与基于环的并发集合通信相比，并发执行它们可将带宽受限的通信时间减少 $(N-2)/(2(N-1))$：四 rank 时为 33%，八 rank 时为 43%。INC-MoE 将 token 划分为 band，并在单个持久化内核中通过三阶段 AllGather-前馈网络（FFN）-ReduceScatter 流水线处理它们。在稳态下，角色专用线程块并发地收集下一个 band、计算当前 band 并归约前一个 band，利用设备侧同步使两个集合通信彼此重叠并与计算重叠。INC-MoE 可作为 vLLM 的 MoE 层的即插即用替代集成。我们在一个模拟的四节点横向扩展部署中评估它，其中专用加速器模拟网内计算（INC）交换机。在采用四路专家并行的 OLMoE 预填充中，相对于 vLLM 的默认集合通信路径，INC-MoE 将首 token 时间（TTFT）最多降低 33%，并将吞吐量最多提高 50%，同时保持其输出一致。

## Abstract
In expert-parallel mixture-of-experts (MoE) serving, dispatch moves tokens to the accelerators hosting their selected experts, and combine returns expert outputs to each token's owner. Both operations lie on the critical path and can dominate MoE layer latency in multi-node deployments. We present INC-MoE, an expert-parallel MoE layer that offloads dispatch and combine to the network switch and overlaps both collectives with each other and with expert computation. Dispatch uses in-network AllGather through switch-side multicast, while combine uses in-network ReduceScatter through switch-side reduction. Both collectives use message semantics between the end hosts and the switch. Because the in-network collectives load opposite directions of each link, executing them concurrently reduces bandwidth-bound communication time by $(N-2)/(2(N-1))$ relative to concurrent ring-based collectives: 33% for four ranks and 43% for eight.   INC-MoE partitions tokens into bands and processes them through a three-stage AllGather-feed-forward network (FFN)-ReduceScatter pipeline inside a single persistent kernel. At steady state, role-specialized thread blocks gather the next band, compute the current band, and reduce the previous band concurrently, overlapping both collectives with each other and with computation using device-side synchronization. INC-MoE integrates as a drop-in replacement for the MoE layer of vLLM. We evaluate it in an emulated four-node scale-out deployment with a dedicated accelerator emulating an in-network computing (INC) switch. On OLMoE prefill with four-way expert parallelism, INC-MoE reduces time to first token (TTFT) by up to 33% and increases throughput by up to 50% relative to vLLM's default collective path, while matching its outputs.

## 1. 核心问题与整体含义

- **研究背景**：在专家并行（EP）的 MoE 推理服务中，每个 MoE 层都需要先 **dispatch**（把 token 发送到承载其选中专家的加速器），再执行专家 FFN，最后 **combine**（把专家输出加权汇总回 token 所属 rank）。这两步都位于关键路径上。
- **核心问题**：在多节点 scale-out 部署中，跨节点带宽远低于节点内带宽，dispatch/combine 的集合通信开销可能主导 MoE 层延迟，使层变为通信受限。
- **现有路径的不足**：
  - vLLM 默认 EP 路径将 dispatch/combine 表达为 **AllGather（AG）+ ReduceScatter（RS）**，但 AG、专家计算、RS 三阶段串行执行，通信时间完全暴露。
  - 仅把集合通信卸载到交换机并不够：在带宽受限区间，单独一个网内 AG 或 RS 仍会饱和链路一个方向，完成时间与 ring 集合通信相当。
  - 仅做计算-通信重叠（micro-batch 或 fused kernel）可以隐藏通信，但不缩短通信本身。
- **论文整体含义**：INC-MoE 将 AG/RS 卸载到具备网内计算（INC）能力的交换机，并在单个持久化内核中把 AG、专家 FFN、RS 以 token band 为粒度流水化，使两个集合通信彼此重叠、并与专家计算重叠，从而缩短 EP MoE 推理的关键路径。

## 2. 方法论

### 2.1 核心思想

- 利用 AG 与 RS 的链路方向不对称性：
  - 网内 **AG 是接收重**：每个 rank 只发送自己的贡献，但需接收其他 \(N-1\) 个 rank 的数据。
  - 网内 **RS 是发送重**：每个 rank 需发送自己的 partial 结果，但只接收一个已归约的 shard。
  - 二者并发时，每个链路方向各承载约 \(S\) 字节，从而同时利用双向链路。
- 将 dispatch 映射为交换机侧多播实现的网内 AG，将 combine 映射为交换机侧归约实现的网内 RS。
- 将每层 token 划分为多个 band，在单个持久化 kernel 中用角色专用线程块分别执行 gather、compute、reduce，形成三阶段流水线。

### 2.2 网内 AG/RS 的消息语义

- 端主机不直接读写其他 rank 的内存；所有传输都是端主机与交换机之间的消息交换。
- **AG**：每个 rank 作为自己贡献的 root，将数据发给交换机；交换机多播给其余 \(N-1\) 个 rank；各 rank 收到其他 root 的贡献后完成 AG。
- **RS**：每个 rank 作为自己输出 shard 的 root；其余 \(N-1\) 个 rank 将 partial 结果分块发给交换机；交换机对每个 chunk 做网内归约并转发给 root；root 再在本地加上自己的 partial，得到最终 shard。
- **数据布局**：所有 rank 的 gather/reduce buffer 按 \(N\) 个 per-rank block 布局，每块 \(T_{\max}=\max_r T_r\) 行；rank \(r\) 的 token 占其 block 的前 \(T_r\) 行。各 rank 依据已知 token 数推导相同布局，无需交换元数据。
- **完成信号**：使用累计完成信号和单调递增的 epoch 阈值，避免 reset 与迟到信号之间的竞争。

### 2.3 通信代价分析

设完整 gathered buffer 大小为 \(S\)，每 rank 链路每方向带宽为 \(BW\)。

- Ring AG/RS 单独执行：每 rank 发送/接收 \((N-1)/N \cdot S\)，时间约为 \((N-1)/N \cdot S/BW\)。
- 网内 AG 单独执行仍受接收方向限制，网内 RS 单独执行仍受发送方向限制，因此单独看与 ring 时间相当。
- Ring AG 与 ring RS 并发：每个方向仍需承载 \(2(N-1)/N \cdot S\)，并发不缩短总时间。
- 网内 AG 与网内 RS 并发：每个方向承载
  \[
  \frac{S}{N}+\frac{N-1}{N}S=S
  \]
  因而通信时间降为 \(S/BW\)。
- 理论提升：
  \[
  1-\frac{t_{\mathrm{INC}}}{t_{\mathrm{ring}}}
  =\frac{N-2}{2(N-1)}
  \]
  - \(N=4\) 时为 33.3%；
  - \(N=8\) 时为 42.9%；
  - \(N\) 增大时趋近 50%；
  - \(N=2\) 时提升为 0。

### 2.4 Band 流水线与角色专用线程块

- 每层启动一个持久化 kernel，线程块分为三类角色：
  - **Gather blocks**：将本 rank 当前 band 的 token 拷入注册发送 buffer，发起网内 AG，等待完成后发布 `agReady`。
  - **Compute blocks**：等待对应 band 的 AG 完成，执行本地专家 FFN，将加权输出直接写入 RS 发送 buffer。
  - **Reduce blocks**：等待所有 compute block 完成当前 band，执行跨 rank band barrier，发起网内 RS，收到交换机 partial sum 后在本地完成 root 加法。
- 稳态下三个 band 同时在飞：
  - 第 \(j+1\) band 的 AG；
  - 第 \(j\) band 的 FFN；
  - 第 \(j-1\) band 的 RS。
- **尾协助（tail assistance）**：最后一个 AG 完成后，gather blocks 加入最后若干 band 的 reduce 工作，缩短 drain 阶段中 RS 单独运行的时间。
- **同步机制**：
  - 设备内存中的 release/acquire flag；
  - 每个生产 block 维护单调递增的 progress counter，消费者只等待所需 counter；
  - 每个 band 的 RS 前执行跨 rank barrier，限制 rank 间漂移不超过一个 band；
  - 空 band 也必须推进 counter 和参与 barrier，避免死锁。

### 2.5 融合专家计算与零拷贝输出

- 每个 (band, expert) 对执行两个 GEMM：gate/up 投影 + SwiGLU，down 投影 + router 加权。
- SwiGLU 在 epilogue 中于寄存器内完成，只把激活后的中间结果写回设备内存。
- down 投影 epilogue 直接将 router 加权结果累加进 RS 发送 buffer \(Z\)，省去额外 weighting/scatter/staging。
- root 的本地归约直接在 \(Z\) 中就地完成，最终输出以 tensor view 暴露给 serving engine，实现零拷贝输出。
- 每个 MoE 层开始时 \(Z\) 清零，保证本地专家贡献正确累加。

### 2.6 流水线配置

- band 数 \(n_b\)、角色线程块分配 \((B_{\mathrm{AG}},B_{\mathrm{FFN}},B_{\mathrm{RS}})\) 和 tail assistance 通过经验扫描确定。
- 最优配置随每加速器 token 数变化；运行时按 token-count regime 选择最佳配置。
- compute block 数是 kernel 编译期参数，因此不同 regime 使用专门化的 kernel 变体。

### 2.7 与 vLLM 集成

- INC-MoE 作为 vLLM MoE 层的 drop-in replacement，位于 router 与专家计算之间。
- 路由逻辑仍由 vLLM 负责，top-k 权重归一化等语义不变。
- per-rank token 数来自 vLLM 的 DP 元数据；模型维度、专家数、top-k、数据类型、EP 度均为运行时参数。
- 适用于专家为 SwiGLU FFN、fp16/bf16 的 MoE 模型。
