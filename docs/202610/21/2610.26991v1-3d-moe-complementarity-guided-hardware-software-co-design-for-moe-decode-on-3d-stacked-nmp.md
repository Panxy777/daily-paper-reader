## 摘要
混合专家（MoE）已成为扩展大语言模型（LLMs）的主流方式，因为每个token仅激活一小部分专家，从而降低推理成本。然而，MoE解码仍然高度受限于内存，并表现出强烈偏斜且随时间变化的专家负载。3D堆叠DRAM近内存处理（NMP）提供了解码所需的带宽，但其分块组织使负载均衡代价高昂：专家并行（EP）保持了局部性，却会遭受热点引发的不均衡；而更分布式的策略会削弱局部性并增加NoC流量。为解决这种局部性与均衡之间的冲突，我们观察到领域专用的token路由会在不同解码步之间产生相互抵消的专家负载波动，我们将这一特性称为专家互补性。基于这一洞察，我们提出3D-MoE，一种面向3D堆叠NMP上MoE解码的软硬件协同设计系统。3D-MoE使用离线一次性、互补性引导的分组与局部性感知映射来建立粗粒度组间均衡，通过轻量级协同内存网络（CMN）处理残余的组内热点，该网络通过重构的本地广播路径将每个热点专家的权重瓦片从其宿主DRAM通道一次性流式传输到辅助核心，并使用代价感知的在线重映射以保持对工作负载漂移的鲁棒性。在多种MoE模型上，3D-MoE相较于EP平均实现4.63倍的MoE层加速，并将端到端吞吐量相较于最强的NMP基线提升1.58倍至1.86倍，仅增加2.11%的逻辑裸片面积。

## Abstract
Mixture-of-Experts (MoE) have become a mainstream way to scale Large Language Models (LLMs), because each token activates only a small subset of experts, reducing inference cost. However, MoE decode remains highly memory-bound and exhibits strongly skewed, time-varying expert loads. 3D-stacked DRAM near-memory processing (NMP) provides the bandwidth that decode demands, yet its tiled organization makes load balancing expensive: expert parallelism (EP) preserves locality but suffers from hotspot-induced imbalance, while more distributed strategies weaken locality and increase NoC traffic.   To address this locality-balance conflict, we observe that domain-specialized token routing creates offsetting expert-load fluctuations across decode steps, a property we call expert complementarity. Using this insight, we propose 3D-MoE, a hardware--software co-designed system for MoE decode on 3D-stacked NMP. 3D-MoE uses offline, one-time complementarity-guided grouping and locality-aware mapping to establish coarse-grained inter-group balance, handles residual intra-group hotspots through a lightweight Collaborative Memory-Network (CMN) that streams each hot expert's weight tiles once from its host DRAM channel to helper cores over a reconfigured local broadcast path, and uses cost-aware online remapping to remain robust to workload drift. Across MoE models, 3D-MoE achieves an average 4.63$\times$ MoE-layer speedup over EP and improves end-to-end throughput by 1.58$\times$--1.86$\times$ over the strongest NMP baselines, with 2.11\% additional logic-die area.

## 1. 核心问题与整体含义（研究动机与背景）

- **MoE 解码的内存墙与负载倾斜**：MoE 通过稀疏激活扩展 LLM 容量，但自回归解码阶段每个专家仅收到少量 token，形成小 GEMM/GEMV，数据复用差、算术强度低，高度受限于内存。作者实测在 batch size 64 时，MoE 层占端到端延迟的 **83%–92%**；同时专家负载高度偏斜且时变，最热专家单步接收超过步均值的 **20×**，单个专家负载在步与层间波动 **2–7×**。
- **3D 堆叠 NMP 的适配与代价不对称**：3D 堆叠 DRAM 近存处理（NMP）利用堆叠 DRAM 下方的逻辑裸片放置 GEMM 引擎，配合 TSV 提供高带宽、低延迟访问，与带宽主导的 MoE 解码高度匹配。但其分块（tiled）组织造成强代价不对称：**本地 DRAM 访问快且带宽充裕，远程访问需穿越 NoC 并消耗共享带宽**。
- **局部性—均衡—通信的三方张力**：
  - 专家并行（EP）保持专家权重局部性，但路由偏斜使承载热专家的核心成为拖尾者；
  - 张量并行（TP）平滑负载，但每次专家调用都变成分布式执行加归约同步，实测 32 核时 NoC 开销达专家执行时间的 **52%**，且削弱核内复用；
  - 动态 EP 方法（重映射、复制、工作窃取）受限于热专家预测困难（已有工作报告低于 50% 准确率）以及权重迁移/远程协助消耗 NoC 带宽。
- **核心挑战**：在 3D 堆叠 NMP 上**保留 EP 的局部性，同时缓解其负载不均衡**。论文的关键洞察是：MoE 路由偏斜并非纯随机，领域专用路由会在不同解码步产生相互抵消的专家负载波动，即**专家互补性（expert complementarity）**，可作为一种 EP 友好的均衡信号。

## 2. 方法论

### 2.1 核心思想

利用"专家互补性"这一 trace 级负载抵消结构，将均衡问题分层处理：**离线粗粒度组间均衡 + 硬件组内残余热点协助 + 在线长期漂移修正**，从而在不牺牲权重局部性的前提下逼近负载均衡。

### 2.2 专家互补性的定义与验证

- **Trace 构建**：对每层、每个专家 e，记录批式服务下第 d 个解码步的路由 token 数 $F_{e,d}$，构成解码步级专家负载 trace。
- **显著性检验**：用 Pearson 相关衡量两条专家 trace 的负载抵消程度；不采用模型无关阈值，而是对每个"模型–数据集"构建设验零分布——将一条 trace 相对另一条循环移位后重算相关，破坏时间对齐但保留边际分布；观测相关低于零分布下 5% 分位数即判定为显著互补对，逐层独立计算。
- **验证结果**：
  - 互补对在领域偏好画像上的余弦相似度低于正相关对和随机对（如 Qwen3：0.25 vs 0.71 / 0.46），支持"互补性源于领域偏好子集间的负载转移"这一解释；
  - 跨模型跨数据集普遍存在：**82.2%–88.3% 的专家至少有一个互补伙伴**，平均约 9.6 个伙伴；跨数据集伙伴保留率 **70.6%–80.5%**；
  - 时间稳定性：前 256 步识别的伙伴在后续三个 256 步窗口保留率为 **94.5% / 92.7% / 90.8%**；
  - 组级均衡：在三种模型、每组 8 专家设置下，相比粗粒度历史负载分组，平均 M2M（最大组负载/平均组负载）降低 **17%**，接近 1.1。

### 2.3 离线互补性引导分组与局部性感知映射

按层独立求解，**两阶段序贯优化**（Gurobi 求解，3% 相对 MIP gap 或 3 分钟超时）：

- **第一阶段：专家分组（分层多目标 ILP）**。决策变量 $B_{e,g}\in\{0,1\}$（专家是否属于组 g）、$D_{e,g}\in[0,1]$（分配给该组的工作负载比例，支持复制）。目标按优先级依次为：
  1. 最小化各组计算代价 $T_{g,d}$ 的组间极差（式 1），其中 $T_{g,d}=\sum_e B_{e,g}D_{e,g}F_{e,d}$；
  2. 在计算均衡可比的前提下，最小化协作代价 $M_{g,d}$ 的组间极差（式 2）；
  3. 最小化总协作代价（式 3）。
- **残余协作代价建模**：定义相对步均负载 $AL_d$ 的成对负载偏移分数 $C_{e_1,e_2,d}$——仅当两专家分居步均两侧时取两侧偏移量的较小值，否则为 0（式 5）；组协作代价为组内成对分数之和（式 6）。保留成对形式是为了让后续映射显式优化协作局部性。
- **第二阶段：物理映射（二元二次放置问题）**。目标（式 7）为 $\sum_{e_1<e_2}\big[\sum_g B_{e_1,g}B_{e_2,g}\sum_d C_{e_1,e_2,d} + \lambda_{route}A_{e_1,e_2}\big]R_{e_1,e_2}$：第一项把可能协作的专家放近，第二项用共激活亲和度 $A$ 把同一 token 常同时选中的专家（多播共同目的地）放近以共享路由段。去掉路由项会使 Qwen3 的 dispatch/gather 延迟平均增加 **47%**。超过单核容量的大专家用 TP 拆分并以"虚拟专家"参与放置，其 all-reduce 通信纳入候选映射评估。
- **约束**：工作负载分配归一（式 8）、组大小均匀（式 9）、核容量上限（式 10），并遵守栈内局部性策略。
- **开销**：每模型用 256 条 prompt × 256 解码步的多域 trace 做一次 profiling，总预处理 **1–3 小时/模型**，部署期摊销；68% 的优化运行达到 3% gap，超时最差 7.1%。

### 2.4 协同内存网络（CMN）——组内热点硬件快速路径

- **动机量化**：2–16 核协助单个热专家时，按需远程取权重比理想延迟高 **29–242%**，单次读取 + NoC 广播仍平均多 **48%**，组内 TP 高 **19–185%**。Flit 级剖析显示固定路由器流水线占平均 flit 延迟的 **63.2%**，动态等待仅 7.8%，说明瓶颈在逐跳包处理而非拥塞。
- **微架构**：每个 NMP 核集成数据转发单元（DFU）、数据接收单元（DRU）和可重构协作链路（RCL）。
  - **DFU** 挂在 3D 内存控制器的 Read Return Buffer 之后，预配置热专家地址范围与辅助核掩码；匹配的 DRAM 读返回时，同时转发给宿主本地 Weight Buffer 和 RCL 路径——**一次 DRAM 读服务所有参与核**。
  - **DRU** 在辅助核侧接收流式瓦片并写入本地 Weight Buffer，供 GEMM 直接消费。
  - **RCL** 复用现有 NoC 链路，在两种相位对齐模式下工作：token dispatch/gather 用标准包传输，热点协作时用临时类总线广播；路由器内集成轻量 Bus Switch 与分布式 Session Arbiter，将选定链路从包流水线剥离并重连为广播路径。
- **三阶段重配置流程**：**Planning**（gating 暴露每专家负载后，运行时调度器识别残余热点、选辅助核、构造协作域与广播调度）→ **Setup**（token 先经常规 NoC 送达辅助核，随后链路进入协作模式，RTL 实测切换 40 周期 = 61.5 ns，不到 CMN 延迟的 0.05%）→ **Execution**（宿主每瓦片只流式广播一次，辅助核在仲裁会话下并行消费，步末链路恢复）。
- **定位**：CMN 只服务残余组内热点，普通 dispatch/gather 与通用核间通信仍走常规 NoC，不替代通用互连。

### 2.5 组内专家调度（Algorithm 1）

利用 gating 在执行前暴露每专家负载的窗口，在栈控制器上运行延迟驱动启发式：按负载降序排列过载核、升序排列欠载核；从最过载源核开始，逐步把欠载辅助核并入候选协作域，形成 `Topology_new`；域上限 16 核且须与活跃域链路不相交；用预测量性能表把 token 数换算为核延迟；在扣除 CMN 协作代价后估算全局 makespan 收益，仅保留正收益候选并生成有序协作调度。性能表覆盖至多 2048 token/专家，约 **4 KB SRAM**。

### 2.6 在线专家重映射

- **负载预测**：对每专家维护 EMA，$EMA_e(t)=\alpha F_e(t)+(1-\alpha)EMA_e(t-1)$，取 $\alpha=0.3$（基于 trace 预测精度调优）。
- **三级调整（按迁移代价递增）**：
  - Tier-1：仅在现有副本间重分配负载比例，不搬权重，**每层执行前都运行**；
  - Tier-2：为过载专家加副本、从欠载专家删冗余副本，需一次权重传输；
  - Tier-3：跨组交换专家，修正严重组间失衡，需两次迁移。
- **代价感知触发**：Tier-2/3 每 8 个解码步检查一次，或在 EMA 预测组级 M2M 连续 3 步超过稳态 20% 时提前触发；按权重体积、传输距离、可用带宽估算收益与迁移代价，仅净收益为正才执行，传输异步并与计算重叠。Qwen3 上每层 256 步平均 **24 次搬权重重映射**，**91% 传输时间被隐藏**，端到端暴露开销仅 **0.87%**。

## 3. 实验设计

- **目标平台**：HBM 风格异构 xPU–NMP 系统，每个 NMP 设备 = 1 个 H100 级 xPU 裸片 + 4 个 16 GB NMP 栈（硅中介层互连）；每栈 16 通道、16 个 NMP 核、4×4 mesh NoC、512-bit 链路，核频率 650 MHz、1.33 TFLOPS、166.4 GB/s 本地 DRAM 带宽、64 KB 缓冲。按模型规模选 NMP-S/M/L（1/2/4 设备）。

- **数据集/工作负载**：服务 trace 来自 LMSys、ShareGPT、MATH、HumanEval；互补性领域画像另用 SciQ、LogiQA。评测 batch size 32–256，固定长度 512/2048 token 及不规则序列长度。
- **模拟器**：基于 Ramulator 2.0（扩展 HBM3 时序与 NMP 核访存）和 BookSim（扩展包交换栈内/栈间流量与栈内 RCL 协作，加入 RTL 推导的 setup/drain 代价）的周期级模拟器；计算按 tile 粒度建模并允许计算/访存/通信重叠；xPU 上稠密算子用 GPU 实测延迟，与 NMP 模拟器组合得到端到端结果。CMN 用 RTL 实现并在 7 nm 下用 Synopsys Design Compiler 综合估算面积与峰值功耗。
- **对比基线**：
  - GPU 参考系统（vLLM 0.8.1，1×/2×/4× H100 配置）；
  - NMP 上：静态 EP、静态 TP、HD-MoE（离线分析后对热专家用 TP、冷专家用 EP 的混合策略）、PS（EPLB 式预测复制与映射）、WS（动态工作窃取）。
- **评测指标**：MoE 解码层延迟/加速比、M2M 比、计算资源利用率、端到端吞吐、归一化 TBT（p50/p90/p99）。
