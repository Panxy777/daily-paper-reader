## 摘要
我们提出 FORGE（Fast On-chip Rotor Generation for Experts，面向专家的快速片上转子生成），一种用于稀疏混合专家（MoE）推理的程序化权重生成系统。我们不再从 HBM 存储并加载每个专家权重张量，而是展示如何利用每个流式多处理器（SM）内部的紧凑加速器，根据每个投影的 O(log^2 d) 个转子参数即时重新生成这些权重。对于每个被替换的层，数 GB 的已存储专家权重可由不足 1 MB 的种子近似。这解决了自回归稀疏 MoE 解码的双重内存瓶颈：在小规模路由 token 数下，逐专家 FFN 操作受 HBM 带宽限制；而专家总占用迫使采用多节点专家并行（EP）并产生 all-to-all 通信。我们将该方法实现为转子生成单元（RGU），这是一种固定功能数据通路，可在不与 Tensor Core 执行竞争的情况下生成 FFN 权重瓦片。在五个稀疏 MoE 模型中替换 30% 的 MoE FFN 层后，我们估计在相同 GPU 数量下系统吞吐量提高 1.3–2.8 倍，在短上下文下每用户解码延迟降低为原来的 1/1.10–1/1.15。作为交换，在三个模型家族上，下游准确率低于未进行转子替换而微调的同一模型，且替换比例控制这一权衡。FORGE 还将 KV 缓存容量扩大 1.2–2.6 倍。它与权重的存储位宽无关，因此可与量化组合使用。RGU 已在 SystemVerilog 中完整实现/验证，SM 面积开销约 0.9%（0.032 mm^2/SM，7nm）。

## Abstract
We introduce FORGE (Fast On-chip Rotor Generation for Experts), a procedural weight generation system for Sparse Mixture-of-Experts (MoE) inference. Rather than storing and loading every expert weight tensor from HBM, we show how a compact accelerator inside each Streaming Multiprocessor can regenerate them on-the-fly from $O(\log^2 d)$ rotor parameters per projection. Per replaced layer, gigabytes of stored expert weights are approximated with under a megabyte of seeds. This addresses the dual memory bottleneck of autoregressive Sparse MoE decode, where per-expert FFN operations are HBM-bandwidth-bound at small routed-token counts and the aggregate expert footprint forces multi-node Expert Parallelism (EP) with all-to-all traffic. We realize the approach as the Rotor Generation Unit (RGU), a fixed-function datapath that generates FFN weight tiles without competing with Tensor Core execution. With 30% of the MoE FFN layers replaced across five Sparse MoE models, we estimate 1.3-2.8x higher system throughput at matched GPU count and 1.10-1.15x lower per-user decode latency at short context. In exchange, downstream accuracy on three model families falls below that of the same model fine-tuned without rotor replacement, and the replacement ratio controls this tradeoff. FORGE also expands KV cache capacity by 1.2-2.6x. It is agnostic to the bit width at which weights are stored, so it can compose with quantization. The RGU is fully implemented/verified in SystemVerilog at ~0.9% SM area overhead (0.032 mm^2/SM, 7nm).

- **研究对象**：稀疏混合专家（Sparse MoE）大模型在**自回归解码**（尤其是短上下文、小 batch 的交互式场景）中的推理瓶颈。
- **根本矛盾**：MoE 专家权重占总参数量的 **94–98%**（五个前沿模型中 FP8 下为 29 GB–728 GB），它们必须常驻 HBM 并在每个 decode step 被反复搬移。论文将其归纳为三重压力：
  - **P1 带宽瓶颈**：top-K 路由使每专家有效 batch 为 $b_{expert}=B\cdot K/E$。例如 DeepSeek-v3.2（K=8, E=256）在 B=32 时每专家仅 1 个 token，FFN 退化为 GEMV，HBM 带宽饱和而 Tensor Core 空闲。实测表明需 $b_{expert}\approx512$（大投影）甚至 4096（小投影）才能达到 50% SM 利用率，对应的服务 batch 高达 1.6 万–6.5 万 token，远超实际交互场景。
  - **P2 容量瓶颈**：多数模型超过单卡 80 GB HBM，被迫采用多节点专家并行（EP），每个 decode step 都要付出跨节点 all-to-all 通信；同时权重挤占 KV cache，限制并发用户数。
  - **P3 量化不改变访问模式**：FP8/INT4 只压缩字节数，GPU 仍需每步从 HBM 取每个激活权重。
- **核心洞察**：三个问题共享一个未被质疑的假设——**专家权重是静态驻留于 HBM 的载荷**。FORGE 提出把每个专家投影视为**可程序化合成的对象**（由"配方"而非张量产生），从而同时缓解带宽与容量问题。
- **整体含义**：这是一篇 **ASPLOS 架构论文**，主张用"计算换存储/带宽"，在 GPU SM 内加入专用硬件按需生成权重，属于 MoE 推理的算法–硬件协同设计。

## 2. 方法论

### 2.1 核心思想：Rotor 程序化参数化
- 基于 Pence et al. [51] 的 Clifford 代数 **rotor** 理论：$O(d^2)$ 的线性投影可由 **$O(\log^2 d)$ 个 rotor 参数（角度）** 近似；这些角度按固定顺序施加旋转即可重建投影。
- **离线阶段**：每个预训练专家被拟合为一个 rotor 参数种子（seed）；**推理阶段**：种子替代稠密专家张量，由片上 **RGU（Rotor Generation Unit）** 实时物化权重瓦片，直接写入 Shared Memory（SMEM）供 Tensor Core 使用，**完全绕过 HBM 权重加载路径**。

### 2.2 关键技术细节
- **分块结构（Chunk）**：设 $d=2^n$，一个 chunk 是 $2^n\times2^n$ 的块对角矩阵，分解为 $n+1$ 个独立块（按 $k\in\{0,\dots,n\}$ 索引），第 $k$ 块尺寸为 $\binom{n}{k}\times\binom{n}{k}$；$k=0$ 与 $k=n$ 为平凡单位块，可零开销跳过。
- **三段式流水线**：Stage 1 将 $d_{in}$ 投影到 chunk 尺寸 $c=2^n$；Stage 2 施加 $m=2$ 个 rotor 映射；Stage 3 投影回 $d_{out}$。每投影 chunk 数为 $\lceil d_{in}/c\rceil+m+\lceil d_{out}/c\rceil$，本文取 $n\in\{9,10,11\}$。
- **单块生成算法（Eq.2 / Algorithm 1）**：从单位阵出发，对 $\binom{n}{2}$ 个旋转轴 $t$ 顺序迭代；每次迭代对若干**不相交行对** $(i,j)$ 按列施加 $2\times2$ 旋转：
  $$\begin{bmatrix}W_i\\W_j\end{bmatrix}\leftarrow\begin{bmatrix}\cos\theta_t & -\sigma_t\sin\theta_t\\ \sigma_t\sin\theta_t & \cos\theta_t\end{bmatrix}\begin{bmatrix}W_i\\W_j\end{bmatrix}$$
  其中 $\sigma_t\in\{+1,-1\}$ 由组合符号奇偶性决定，行对集合与符号均由 $(n,k,p,q)$ 静态确定。
- **三条正交并行轴**（本文相对 [51] 的关键重构）：
  1. **列独立** → 64 宽 SIMD 数据通路；
  2. **行对独立**（同一轴下 $\binom{n-2}{k-1}$ 个行对互不相交）→ 可调度并行；
  3. **$k$-block 独立** → 与 GEMM tile 粒度对齐。
- **Supertile 概念**：一个 $k$-block 的全部 $\binom{n}{k}$ 行 × 64 列的权重瓦片，恰好对应一个 GEMM thread-block tile；由于 $\binom{n}{k}$ 常大于 BlockItemsK（FP8 下约 128），同一 Supertile 可被 $n_{stile}=\lceil\binom{n}{k}/\text{BlockItemsK}\rceil$ 次 GEMM 迭代复用，摊薄生成延迟。
- **执行模型**：$T_{rotor}=\max(T_{compute}, T_{mem\_input}, T_{supertile\_gen}/n_{stile})$；当摊薄后的生成延迟低于被替代的 HBM 传输时间时，执行从带宽受限转为计算受限。

### 2.3 RGU 微架构（SystemVerilog 实现）
- **总体**：FP8 双行对架构，每 2 周期处理两个独立行对，64×2 SIMD。
- **Supertile Address Generator (SAG)**：不存储完整 $(i,j)$ 轨迹（$n=11$ 时需数万条目），而是用 **0.5 KB Base ROM** 存 512 个基础组合模式，组合逻辑注入轴位 $p,q$ 生成行掩码，再由 **9 KB Mapping ROM** 翻译为物理 SRAM 索引；符号 $\sigma_t$ 由奇偶校验组合计算，无需存储表。
- **Supertile SRAM**：4 个 1R1W bank 交织（每 bank 深 116），合成 2R2W 等效带宽，共 28.875 KB（462×512 bit），避免多端口 SRAM 的面积开销。
- **PE 阵列**：3 级流水 FMA（两级乘法 + 一级加法），稳态 2 周期/行对吞吐；参数缓冲 0.43 KB 存 220 组 $(\cos\theta_t,\sin\theta_t)$，在轴边界锁存并广播。
- **静态无冲突调度**：离线用最大匹配在 bank 冲突图上求解，将无冲突行对顺序存入 Schedule ROM，运行时**零动态仲裁**；轴边界注入固定 5 周期 stall 消除 RAW 冒险。
- **输出**：Output Streamer 在写出时直接施加 Phase-XOR swizzle；单位块直接注入 1.0，零生成周期。

## 6. 主要结论与发现

- **Kernel 级**：8 token/专家时每专家 MoE FFN 加速 **2.3–3.2×**（峰值在 n=10 的 Qwen3-235B，3.23×）；16 token/专家时收窄至 1.13–1.67×，证实 RGU 瞄准的是内存受限区间。绝对延迟如 DeepSeek-v3.2 从 23.48 μs 降至 10.06 μs。
- **Decode 延迟**：r=0.3 时短上下文降低 **1.10–1.15×**，128K 上下文仍有 1.07–1.11×（KV cache 稀释效应）。
- **系统吞吐**：同 GPU 数下 **1.3–2.8×**；r=0.7 外推可达 2.0–6.1×。
- **容量**：KV cache 扩大 **1.2–2.6×**（4K）至 1.1–3.5×（128K）；总参数内存减少 **28–29%**；DeepSeek-v3.2/GLM-5 的最小 GPU 数从 10/11 降至 7/8，可装入单 NVLink 节点，消除跨节点 all-to-all。
