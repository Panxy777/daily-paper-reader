## 摘要
不规则 All-to-All 通信是专家并行混合专家（MoE）模型中的主要瓶颈。即使专家路由和放置固定，并行网络 Rail 利用不均与 incast 也会限制通信性能。我们提出 RailWave，一个构建于 DeepEP 之上的阶段自适应通信层，通过空间与时间流量整形在路由层之下解决这些瓶颈。RailBalance 利用源端局部信息将源流量重新分布到可用 Rail 上，而一个可复用的、由拓扑导出的置换调度限制每个接收方的并发发送方数量，无需为每个通信阶段重建依赖需求的调度。一个轻量级校准选择器根据每个阶段的流量特征和离线剖析结果选择执行路径。在来自 106B GLM-4.5-Air 模型的训练衍生通信工作负载上，RailWave 相比 Native 在 H800 上最高实现 5.84 倍加速，在 H20 上最高实现 4.36 倍加速。代码见 https://github.com/CyberSecurityErial/RailWave-EP。

## Abstract
Irregular All-to-All communication is a major bottleneck in expert-parallel Mixture-of-Experts (MoE) models. Even with fixed expert routing and placement, uneven utilization of parallel network Rails and incast can limit communication performance. We present RailWave, a phase-adaptive communication layer built on DeepEP that addresses these bottlenecks below the routing layer through spatial and temporal traffic shaping. RailBalance redistributes source traffic across eligible Rails using source-local information, while a reusable, topology-derived permutation schedule limits concurrent senders per receiver without rebuilding demand-dependent schedules for each communication phase. A lightweight calibrated selector chooses an execution path according to each phase's traffic characteristics and offline profiling results. On training-derived communication workloads from the 106B GLM-4.5-Air model, RailWave delivers up to 5.84x speedup on H800 and 4.36x on H20 over Native. Code is available at https://github.com/CyberSecurityErial/RailWave-EP.

## 一、核心问题与研究动机

- **背景**：MoE 通过专家并行（EP）把专家分散到多张 GPU 上，token 的 dispatch/combine 构成**不规则 All-to-All** 通信，是 MoE 训练/推理的主要瓶颈。
- **关键观察**：现有工作（EPLB、UltraEP、MoonEP、TAOT、NetMoE、node-limited routing 等）主要在**路由层/放置层**改变逻辑通信需求矩阵 $D$；但即使 $D$ 固定，**物理执行方式**仍未被决定，在 Rail-optimized 集群（多张 NIC / 多条 scale-out Rail）上仍有大量优化空间。
- **两个被识别的瓶颈**（图 1）：
  - **(a) Rail 不均衡**：专家负载、目的节点负载都均衡时，源端某条 Rail 仍可能成为热点，并行路径闲置。
  - **(b) 接收端 incast**：源端各 Rail 均衡，也不妨碍多个发送方同时涌向同一接收方。
- **量化证据**：
  - 分析 900 个「训练 step–layer」路由记录，专家负载不均衡对源端/目的端 Rail 不均衡的线性解释力仅 $R^2=0.019$ / $0.296$，说明**专家负载均衡 ≠ Rail 均衡**，二者需分别处理。
  - 固定 rank-to-rank 需求、payload、后端与通信轮数，仅改变并发顺序，P50 dispatch–combine 总时延从 1.801 s 升至 3.009 s（**+67.1%**），证明 incast 是独立瓶颈。
- **整体含义**：应在**路由层之下**增加一个通用的「空间（走哪条 Rail）+ 时间（哪些节点对并发）」流量整形层，且不改变专家分配与逻辑需求。

## 二、方法论

### 2.1 总体框架

- RailWave 构建在 **DeepEP** 之上，三阶段流程：**准备（离线剖析 + 拓扑派生 peer plan）→ 选择（按相位流量特征查表）→ 执行**。
- 暴露四条执行路径：
  - `NATIVE`：保持后端原路径；
  - `RAIL-ONLY`：只改出口 Rail 分配；
  - `PERMUTATION-ONLY`：只改并发节点对；
  - `JOINT`：在每个调度波内再叠加 RailBalance（默认兜底路径）。
- 选中计划同时记录**传输顺序**与 **owner→proxy 映射**；dispatch 按计划发送，combine 用保存的元数据把输出还原到原 token 位置；所有 rank 遵循同一路径与波序，且该计划在一对 dispatch–combine 内保持不变。

### 2.2 RailBalance：源端局部空间整形

- 目标：把节点对 $(s,d)$ 的流量在其**可用 Rail 集合** $\mathcal{R}_{s,d}$ 上重分配，**不需要目的端配额交换**。
- 关键性质：在 Rail 对称拓扑下 $\chi_{s,d}(r)=r$，源端的 ingress 贡献只是其 egress 分配的一个**置换**，因此「源端本地均衡」同时塑造了两端；但这是**逐源保证**，聚合层面的完全相等还取决于可用集合与整数余数分布。
- 配额规则：
  - 设 $B_{s,d}=\sum_r C_{s,r,d}$，$m_{s,d}=|\mathcal{R}_{s,d}|$，则 $Q_{s,r,d}\in\{\lfloor B/m\rfloor,\lceil B/m\rceil\}$ 且 $\sum_r Q_{s,r,d}=B_{s,d}$，集合外配额为 0；
  - 余数所有权在目的切片间**确定性轮转**，各可用配额相差不超过 1 条记录。
- 搬迁算法（Algorithm 1）：
  1. 每条 Rail 保留前 $\min(C_{s,r,d},Q_{s,r,d})$ 条记录（配额内不动）；
  2. 超出者进入**盈余队列 S**，不足者进入**缺口队列 D**；
  3. S 按 (owner Rail, 本地索引) 排序，D 按 (目标 Rail, slot 索引) 排序，按序一一配对，得到 owner→proxy 映射；
  4. 只有非恒等映射才需搬迁，token 位置与专家元数据保留供 combine 使用；**无需原子 slot 分配**。

### 2.3 可复用置换调度：时间整形（限制 incast 度）

- 采用**循环成对交换**：$N$ 个节点，第 $k\in\{1,\dots,N-1\}$ 波使用
  $$\pi_k(s)=(s+k)\bmod N,\qquad \pi_k^{-1}(d)=(d-k)\bmod N$$
- 每波每节点**至多一个出边、一个入边**；任意有序节点对的位移 $(d-s)\bmod N$ 唯一，因此**每个远端有序对恰好出现一次**，总通信量与波数不变。
- peer 关系**只依赖组成员关系**，初始化构造一次，后续每个通信阶段只灌入新的传输记录与计数，**不需要按需求重建调度**（这正是与 FAST 的 Birkhoff 类需求相关调度的主要区别）。
- 波内执行：只挑选目的为 $\pi_k(s)$ 的记录，按节点对实际需求打包、**不做 padding**；波内不相交的节点对并发。
- `JOINT` = 在当前波的记录上再施加 RailBalance：某相位整体均衡、但单个目的切片仍集中时可缩短该波的关键传输；收益取决于该切片的 Rail skew 与搬迁代价，且波仍被串行化。

### 2.4 校准式执行选择

- 三个流量描述子（第 2.2 节定义）：
  - $B$：每 GPU 平均远端 payload（规模）；
  - $\rho_g=\dfrac{\max_{s,r}L_{s,r}}{\frac{1}{NR}\sum_{s,r}L_{s,r}}$：全局源端 Rail skew（1 表示完全均衡）；
  - $\kappa=\max_w \max_d \dfrac{R_{w,d}}{\frac1N\sum_d R_{w,d}}$：实际发送窗口下的接收端集中度。
- 归一化（固定工程尺度，非拟合参数）：$\tilde B=\log_2(B/56)$，$\tilde\rho=(\rho_g-1)/7$，$\tilde\kappa=(\kappa-1)/2$；无远端负载时走 Native 本地路径。
- 离线建立**锚点表**，候选替代路径仅在测量稳定且相对 Joint 有**保守优势**时保留：要求 p90/p10 ≤ 1.2（波动 ≤ 20%），且 p10(Joint)/p90(candidate) ≥ 1.05（跨分位保守比较仍有 5% 优势）；低竞争开发用例还要求等价路径控制在 10% 内。最终只留下 **4 个锚点**（7 MiB/Permutation、7 MiB 高 κ/Permutation、14 MiB/Permutation、28 MiB/Native）。
- 运行时：锚点邻域 $A(x)=\{j: |x_m-x_{j,m}|\le\epsilon_m,\forall m\}$（payload 在 1.25× 内、两个形状坐标在 0.02 内），取最近锚点决策；**邻域为空则回退 Joint**，避免外推到未验证的流量区域。
