## 摘要
混合专家（Mixture-of-Experts，MoE）已成为扩展大语言模型的主流方法，因为它能在几乎保持计算成本不变的同时扩展模型容量。训练大规模 MoE 模型依赖于专家并行（Expert Parallelism，EP），它将专家副本分布到不同 GPU 上，并通过全对全通信交换 token。EP 的效率通常受两个系统瓶颈制约：跨节点 token 传输受节点间带宽限制，而专家工作负载倾斜会导致不同 GPU 之间的计算不均衡。已有工作基于单个专家的工作负载统计来缓解这些瓶颈，但忽略了专家之间可以共享通信这一事实。在本工作中，我们通过实证观察到，许多专家对会频繁地被同一个 token 共同激活。受此启发，我们提出 Cobalt，一个高效的 MoE 训练框架，利用专家共激活来减少跨节点流量和工作负载不均衡。Cobalt 采用两阶段专家布局规划器，使专家布局适应不断变化的专家共激活和工作负载状况。它周期性地将频繁共激活的专家共置到同一节点上，以减少跨节点通信，并执行每步的节点内调整以重新平衡工作负载。随后，我们开发了一种通信感知的任务分配方法，该方法基于当前专家布局将 token 路由到更少的远程节点。在 32 块 B200 GPU 上的实验表明，与现有 MoE 训练框架相比，Cobalt 实现了最高 1.53–2.41 倍（平均 1.28–1.89 倍）的加速，同时将跨节点 token 流量降低了 75.74%–99.26%。

## Abstract
Mixture-of-Experts (MoE) has increasingly become a mainstream approach for scaling large language models, as it expands model capacity while keeping computation cost nearly constant. Training large-scale MoE models relies on Expert Parallelism (EP), which distributes expert replicas across GPUs and exchanges tokens through all-to-all communication. The efficiency of EP is often constrained by two system bottlenecks: cross-node token transfers are limited by inter-node bandwidth, while skewed expert workloads lead to imbalanced computation across GPUs. Prior work mitigates these bottlenecks based on per-expert workload statistics, but overlooks the fact that experts could share the communication.   In this work, we empirically present the observation that many pairs of experts are frequently co-activated by individual tokens. Motivated by this, we present Cobalt, an efficient MoE training framework that leverages expert co-activation to reduce cross-node traffic and workload imbalance. Cobalt adopts a two-stage expert layout planner that adapts expert layout to the evolving expert co-activation and workload conditions. It periodically co-locates frequently co-activated experts on the same node to reduce the cross-node communication, and performs per-step intra-node adjustment to rebalance the workloads. Subsequently, we develop a communication-aware task assignment method that routes tokens to fewer remote nodes based on the current expert layout. Experiments on 32 B200 GPUs show that Cobalt achieves up to 1.53-2.41 times (1.28-1.89 times on average) of speedup compared to existing MoE training frameworks, while reducing cross-node token traffic by 75.74%-99.26%.

## 1. 核心问题与研究背景

- **背景**：MoE 已成为扩展 LLM 的主流架构，在扩大参数规模的同时几乎保持每 token 计算量不变。大规模 MoE 训练依赖**专家并行（EP）**：把专家副本分散到不同 GPU，通过两次 all-to-all（dispatch / combine）交换 token。
- **瓶颈一：跨节点带宽**。作者对 Hunyuan3、GLM-4.5-Air、DeepSeek-V3 做性能剖析，发现 MoE 通信占训练时间的 **58%–83%**，且随 EP 度增大而上升。节点内 NVLink 带宽为 1.8 TB/s，节点间 InfiniBand 总带宽仅 400 GB/s，二者相差约 4.5 倍。
- **瓶颈二：专家负载倾斜**。不同专家的 token 数差异巨大，导致部分 GPU 计算量过重、出现长尾（straggler）。
- **关键机制洞察**：DeepEP 等通信库在**节点级对 token 传输去重**——同一 token 若被同一远程节点上的多个专家选中，只需跨节点传一次，再在节点内转发。因此跨节点流量取决于“每个 token 选中了多少个不同的远程节点”，而非专家个数。
- **已有工作的盲区**：FasterMoE、SmartMoE、FlexMoE、LAER-MoE 等均基于**单专家工作负载统计**做复制与放置，忽略了“专家之间可以共享同一次跨节点传输”这一事实。
- **实证观察（新视角）**：作者在 GLM-4.5-Air 训练中按专家对统计 token 集合的 **Ochiai 相似度**（|A∩B|/√(|A||B|)），发现：
  - 平均相似度随训练显著上升（Layer 35：0.41→0.89；Layer 41：0.28→0.86），即**专家共激活普遍存在且随训练增强**；
  - 具体的共激活专家对在训练中不断变化（热力图随时间漂移）；
  - 各专家负载分布也随时间剧烈变化。
- **由此引出两个挑战**：① 单纯把共激活专家放在同一节点会集中负载、造成长尾，必须在减少跨节点流量与保持负载均衡之间权衡；② 共激活关系与负载都在演化，布局必须**自适应调整**，且调整开销不能吞噬收益。

## 2. 方法论

### 2.1 核心思想
将“专家布局（复制 + 放置）”与“token–专家任务分配”解耦：**周期性**基于历史共激活与负载统计做全局布局优化（跨节点搬参数，代价高但频率低），**每步**做节点内副本重排（走 NVLink，代价低），再对每个 token 做**通信感知的在线任务分配**，使其访问尽量少的远程节点。

### 2.2 问题形式化
- 决策变量：专家布局 `P = {P_r}`（rank r 上持有的专家集合，同时刻画复制数与放置）；任务分配 `r_te`（任务 (t,e) 在哪个 rank 执行）。
- 目标：最小化跨节点 token 传输总量
  `V = Σ_t | ∪_{e∈D_t}{N(r_te)} \ {N(s_t)} |`，即每个 token 的目的节点集合（去掉源节点）大小之和。
- 约束：① 每个专家至少 1 个副本；② 每 rank 副本槽位 ≤ `(1+ρ)E/G`（ρ 为副本预算，防显存溢出）；③ 任务必须落在持有该专家副本的 rank 上；④ 每 rank 负载 ≤ `(1+ε)KT/G`（ε 为不均衡容忍度）。

### 2.3 阶段一：周期性全局规划（每 10 步）
- 因规划时拿不到当前 batch 的逐 token top-K 选择，改用两组 EMA 统计：`ŵ_e`（专家 e 被分配的任务数 EMA）与 `ĉ_ij`（同时选中专家 i、j 的 token 数 EMA）。
- 目标从“最小化跨节点通信”**等价转化为“最大化同节点内共激活总量”**：`max Σ_n Σ_{i<j} ĉ_ij · I[i,j 均在节点 n 有副本]`，同时引入辅助变量 `w'_er` 表示专家 e 在 rank r 的期望负载，并保留副本预算与负载上限约束。
- 该问题被改写为 **MILP**（变量 `x_er∈{0,1}` 表示是否放置、`u_en` 表示节点是否持有该专家、`z_ijn` 表示节点是否同时持有两专家、`l_er` 为负载划分；仅 `x_er` 需整数），用 **SCIP** 在 CPU 上求解，并与训练计算重叠。
- 输出：新的专家布局 + 各副本的期望负载划分 `w'_er`（作为阶段二 EMA 的初值）。

### 2.4 阶段二：每步节点内重平衡
- 在两次全局规划之间，用**副本级**任务数 EMA 估计各副本负载，将“节点内副本到 rank 的划分”建模为 min-sum set partitioning 的变体（附加约束：同一专家的两个副本不能同 rank；每 rank 副本数 ≤ `(1+ρ)E/G`）。
- 采用**贪心 bin-packing**：按 EMA 负载排序后贪心装箱，最小化最重 rank 的负载。速度快，可被模型计算完全掩盖。

### 2.5 通信感知的任务分配（GPU kernel，Triton 实现）
- **Step 1 选执行节点**：已在源节点上的专家就地执行；剩余专家集合 `U_t` 转化为**最小集合覆盖**问题——用 `(N−1)` 位掩码标记每个专家的可用远程节点，枚举所有掩码（共 `2^{N-1}` 个）取可行且 popcount 最小者，即为访问远程节点最少的方案。
- **Step 2 选执行 rank**：在选定节点内对副本**均匀随机采样**，使同专家各副本期望负载相同，与阶段二的节点内均衡相呼应。
- 复杂度 `O(T·2^{N-1})`，`2^{N-1}` 在实际 EP 度下近似常数（如 32 GPU / 8 卡每节点 → 2³=8），且对 T 个 token 并行，开销 <1 ms。
- 值得注意：任务分配**不显式施加负载约束**，均衡由阶段一/二保证、由均匀采样维持。

### 2.6 实现
PyTorch + DeepEP 后端；MILP 与 bin-packing 在 CPU 求解；任务分配为 Triton GPU kernel；默认每 10 步触发全局布局更新；节点内重平衡在参数预取后立即执行以被计算掩盖。

## 6. 主要结论与发现

- **实证发现**：专家共激活（Ochiai 相似度）在训练中普遍存在且持续增强（平均从 0.28–0.41 升至 0.86–0.89），但具体共激活专家对与各专家负载均随训练漂移——因此布局必须自适应。
- **性能**：相对 EP+FSDP、SmartMoE、LAER-MoE 分别最高加速 **2.41× / 2.04× / 1.53×**（平均 1.89× / 1.52× / 1.28×）；整体区间 1.53–2.41×（平均 1.28–1.89×）。
- **通信**：跨

**通信**：跨节点 token 传输量相对 EP+FSDP、SmartMoE、LAER-MoE 显著下降；在消融中，周期性全局规划（P）单项即带来约 **95.3%** 的跨节点通信量削减，说明“按共激活对做副本聚合”是收益的主要来源；在与 LAER-MoE 处于可比负载不均衡水平时，COBALT 的通信量仍低 **30.71%–78.29%**。

- **负载均衡**：节点内重平衡（I）把负载不均衡比从 **3.35 降至 1.28**，且几乎不增加可见开销（被计算掩盖），验证了“全局布局负责通信、步级重排负责均衡”的解耦设计是有效的。

- **消融结论（GLM-4.5-Air / EP16，8 种组合）**：三项技术的作用互补而非冗余——P 主攻通信量、I 主攻长尾、T（通信感知任务分配）在二者基础上进一步压低每 token 的远程节点数；去掉任一项都会同时恶化步时间与至少一项辅助指标，三项全开时步时间最短。

- **开销可控**：全局 MILP 规划与节点内 bin-packing 的求解时间均远小于一个训练步，且与计算重叠；布局参数搬运（跨节点）虽为高代价操作，但因每 10 步才触发一次，摊销后对步时间的影响有限，说明“低频重布局 + 高频轻调整”的频率设定是合理的工程折中。

- **可扩展性**：从 8 → 16 → 32 GPU，COBALT 相对基线的吞吐优势随规模扩大而增大，符合“EP 度越大、跨节点流量占比越高、共激活去重收益越大”的机理预期。

- **超参敏感性**：性能对副本预算 ρ 与不均衡容忍度 ε 呈单峰/平缓趋势——ρ 过小限制布局自由度、过大则挤占显存与槽位；ε 过紧会迫使布局牺牲通信换取均衡。默认 ρ=0.5、ε=0.15 位于较优区间，表明方法对超参不敏感、易于落地。

## 7. 方法层面的局限与可讨论之处

- **统计与决策的时滞**：全局规划基于 EMA 历史统计，而规划时无法获知当前 batch 的逐 token top-K 选择；当共激活模式在 10 步窗口内快速漂移时，布局可能“追不上”真实分布。论文虽用实证说明了相似度的缓变趋势，但未量化“统计陈旧度”对收益的衰减。

- **目标函数的近似性**：把“最小化跨节点流量”等价改写为“最大化同节点共激活量”，隐含假设 token 在节点间的分布与共激活统计一致；在极端倾斜（少数专家被大量 token 选中）时，该等价关系可能松动。

- **负载约束的“软”实现**：任务分配 kernel 本身不施加负载约束，均衡依赖阶段一/二的布局与均匀随机采样来“期望性”保证。这在稳态下有效，但在分布突变时可能出现瞬时热点，论文未报告尾延迟（p99 步时间）等更严格的指标。

- **复制粒度为整专家**：副本预算以“专家副本槽位”计，未考虑专家内部参数分片或更细粒度的部分复制，可能在显存极紧张的场景下限制布局空间。

- **MILP 的可扩展性边界**：变量规模随专家数 × rank 数 × 节点数增长，当前 128–256 专家、32 GPU 下可解；若扩展到数百 GPU 或上千专家，需依赖分解/启发式，论文未讨论该拐点。

## 8. 总体评价与启示

- **贡献定位**：本文的核心贡献不在于新的并行范式，而在于**重新定义了 MoE 跨节点通信的计量单位**——从“每专家被选中次数”转为“每 token 触及的不同远程节点数”，并据此把“专家共激活”从一种观察现象升级为可优化的布局目标。这一视角转换具有较强的启发性，可迁移到任何具备节点级去重的 EP 通信库（如 DeepEP 类实现）。

- **工程完整性**：方法被拆成“低频全局 MILP + 高频节点内装箱 + 每步 GPU 侧集合覆盖”三层，代价与收益的层级匹配清晰；实现基于 PyTorch + DeepEP + Triton，且明确报告了调整开销，具备较强的可复现性与落地参考价值。

- **证据强度**：三模型 × 两 EP 度的端到端结果、逐项消融、开销表、敏感性与扩展性实验构成了较完整的证据链；统一使用 DeepEP 保证公平性、5 次重复报告均值±标准差，方法学规范。主要短板在于**单集群、单数据集、最大 32 GPU**，以及**缺少收敛性与模型质量验证**——布局每 10 步变动是否会引入训练不稳定性，仍是开放问题。

- **对后续工作的启示**：① 可将共激活统计与路由决策联动（如路由侧引入轻微的位置偏好），把“事后布局”变为“事前协同”；② 用在线学习/预测替代 EMA，缓解统计时滞；③ 在更大规模集群上验证 MILP 分解策略与尾延迟表现；④ 补充 loss/下游指标曲线，回答“动态布局是否影响收敛”这一审稿人最关心的问题。
